# 多仓迁移落地

技能点：[[Flyway与多仓迁移]] · 项目：[[muou]] · 2026-09~10

场景：多仓共库（待建场景页）

## 我想干什么

muou 的 core 库由 iam / member / platform / content 四个独立仓库共同写入，billing / message / log 各有自己的库。目标是：每个服务只在自己的仓库里记表结构变更，但最终能拼出一份「这个库按什么顺序变成这样」的可执行 SQL，生产由人审核后执行。

## 我干了什么

- **共库登记**：`迁移编写约定.md` 列出服务仓 → 库 → 迁移目录的对应表，core 四仓、billing、message、log 各自的落点写死（`muou-backend/muou-app-ops/databases/迁移编写约定.md:9-19`）。
- **时间戳版本号**：`V<yyyyMMddHHmm>__说明.sql`，跨仓天然不撞；实测 7 个服务/公共仓共 446 份迁移（另加 ops 基线 21 份，整合后 467 份），全部是 12 位时间戳（`迁移编写约定.md:41-52`）。
- **收集整合**：`collect.sh` 收本仓基线 + 各服务仓 `-app/db/migration/<库>/` + 公共库 `_all/`，按版本排序、查重、拼接（`muou-backend/muou-app-ops/databases/collect.sh:60-95`、`:141-173`）。
- **实际规模**：core 库 372 份来源（iam 52 + member 59 + platform 76 + content 170 + ops 基线 15），billing 44、log 7、message 44，共 467 份（446 + 21）（`muou-backend/muou-app-ops/databases/build/*.manifest` 行数）。
- **CI**：静态校验（版本号重复 / `DROP COLUMN` / 列注释）+ 收集校验（克隆 7 个仓、重出 `build/`、`git diff` 查过期）+ 每库一个手动迁移 job（`muou-backend/muou-app-ops/databases/.gitlab-ci.yml:36-86`）。
- **生产口径**：Flyway 只用于开发/测试；生产执行 `build/<库>.sql`，由人触发（`迁移编写约定.md:4`、`:87-88`）。

## 犯了什么错 / 误判

1. **仓库根下的 `db/` 被静默漏收**：2026-09-22 前迁移放在仓库根下，`collect.sh` 的通配收不到；结果是 `build/` 停在 09-17，iam 09-21 落在根下的六份一份都没进去，而产物看起来完整。现在脚本遇到根下迁移会当场报错并打出新路径（`collect.sh:70-88`）。
2. **`_all/` 只是机制，没有内容**：公共表展开写在脚本里，但目录当前只有 `.gitkeep`，没有实际公共表脚本可验证（`collect.sh:49`、目录实测）。
3. **注释门禁的覆盖范围被说大了**：README 写「CI 全 schema 扫描」（`README.md:65`），但 `validate-migrations.sh` 只扫本仓 `migration/<db>`，服务仓的 446 份没有同等扫描。
4. **建外键的口径打架**：单体期 02-0 要求建外键，现行多仓 README 明确不建、四份 init 里 `FOREIGN KEY` 计数为 0（`README.md:66-70`）；照旧文档写会建出退役目录里那批旧外键。
5. **档案仓不在 core 收集范围**：`voidtech-server-archive` 有自己的 21 份迁移，`collect.sh` 只收 core/billing/message/log；上面 467 份不含档案仓，别写成「所有仓都收进来了」。

## 怎么解决

- 收集失败要整次失败，不许跳过文件——跳过等于产出一份少几条变更但看起来完整的 SQL（`collect.sh:149-159`）。
- `build/` 与 `.manifest` 提交进仓库，`validate:collected` 用 `git diff` 查过期（`.gitlab-ci.yml:47-59`）。
- `--stage` 另出一份按版本命名的目录，给 Flyway 当 locations（`collect.sh:203-212`）。
- 迁移头注释写清「本份按空库交付，不能直接照搬到有数据的库」（`V202609211809__iam_psn_rename.sql:7-9`）。

## 现在的规矩

- 迁移写在各自 service 仓的 `-app/db/migration/<库>/`，不写仓库根下。
- 版本号一律时间戳；文件名不合规、撞号、根下脚本，收集时直接失败。
- 生产执行 `build/<库>.sql`，不跑 Flyway。
- 公共表放 `_all/`，由收集脚本展开到三个业务库。
