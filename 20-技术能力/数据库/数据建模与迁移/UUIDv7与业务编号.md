# UUIDv7 与业务编号

技能点：[[数据建模]] · 方法：技术主键与业务编号分离 · 通用技能：[[数据建模与迁移]]

**什么时候会遇到**：新建一张表要定主键；接口要对外暴露一个「单号」；多表事务要在 INSERT 前拿到 ID；或者要从别的库合并数据、担心主键冲突。

## 判断顺序

1. **这个值会对外出现吗？** 会 → 用业务编号（`psn` / `no` / `code`）；不会 → 主键只在内部用。
2. **主键要在 INSERT 之前拿到吗？** 要（父子表同事务、写 Outbox、写审计 target）→ 必须应用侧生成，不能等数据库返回。
3. **主键要时间有序吗？** 要 → UUIDv7（前 48 位毫秒时间戳），B-tree 插入接近追加写。
4. **业务编号什么时候分配？** 业务事件发生时（订单建单、审核通过），所以它不能当主键。
5. **编号唯一性怎么保证？** 业务层锁：先查后插 + 行锁 / 分布式锁，冲突返回 409；不建 DB 唯一约束。

## 手段

- 主键列 `uuid`，列名 `<实体单数>_id`，DDL 不写 `DEFAULT`（`muou-server/docs/02-0-建表通用约束.md:245-248`）。
- 应用侧 `UuidUtil.nextId()`；同一毫秒内单调递增，避免同事务连写排序乱序（`muou-server/src/main/java/com/voidtech/muou/common/util/UuidUtil.java:8-52`）。
- 实体 `@TableId(type = IdType.INPUT)`，DaoImpl 显式赋值；不是 `ASSIGN_UUID`（`02-0-建表通用约束.md:264-289`）。
- 业务编号单独一列，对外只暴露编号（`02-0-建表通用约束.md:293`）。
- 编号发号走 `numbering_sequence` 行锁 + `UPDATE ... RETURNING`，事务回滚则号一起回滚，无空洞（`02-0-建表通用约束.md:157-169`）。

## 反例 / 边界

- **自增 / 雪花**：主键可枚举，跨表批量写要等 `nextval`，分区表还要全局序列协调（`02-0-建表通用约束.md:245-248`）。
- **UUIDv4**：完全随机，B-tree 插入点分散，十万级以上写放大明显（`muou_arch/docs/ddl-conventions.md:45-51`）。
- **业务编号当主键**：编号在业务事件发生时才分配（`identity.no` 待生效时为空），格式含日期与租户前缀，规则一改就是主键变更（`ddl-conventions.md:47-49`）。
- **暴露主键**：UUIDv7 前 48 位是时间戳，暴露即泄露创建时间（`02-0-建表通用约束.md:293`）。
- 没有实测过 UUIDv7 vs bigserial 的索引大小/写入吞吐；「接近追加写」来自文档判断，不是我的基准测试。

## 现在的规矩

- 新表主键一律 `uuid` + 应用侧 UUIDv7，列名 `<实体单数>_id`。
- 业务编号独立成列，对外只给编号。
- 唯一性由业务层锁保证，不建 DB 唯一约束。
- 例外：Casbin 适配器固定 `id`、复合主键表、平台注册表用业务码作主键（`02-0-建表通用约束.md:250-257`）。
