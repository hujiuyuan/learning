# 登录日志租户隔离

技能点：[[MySQL]] · 项目：[[smart WMS]] · 2026-05-15 · 通用技能：[[查询性能优化]]
场景：[[租户字段与查询过滤]]、[[字段调整与冗余]]

## 我想干什么

`login_log` 当前没有租户隔离：任何有 `log:list` 权限的账号都能看到全部登录日志。要改成：子公司只看自家，平台/超管看全部（含 NULL），代登录日志固定 NULL 仅平台可见。

## 我做了什么

- 调研发现 `login_log` 没有 `tenant_id`，`Mapper.xml` 的 `pageLogs` 也没有租户条件。
- 写方案：`login_log` 加 `tenant_id BIGINT DEFAULT NULL`；不加索引（`idx_created_at` 已够）；不 backfill 历史数据。
- 写日志按语义拆成 5 个方法：`recordLogin` / `recordLoginAttempt` / `recordLogout` / `recordImpStart` / `recordImpStop`；`tenant_id` 由 service 内部按语义决定，调用方不拼。
- 读日志 `POST /log/page`：`callerTenantId=null` 不过滤；非空加 `tenant_id = ?` 严格匹配，NULL 行子公司不可见。
- `nickName` 加进 JWT payload，logout/代登录不再反查 `wms_user`。

## 方案里修正过什么

1. 原模块完全没有租户隔离，`Mapper.xml` 的 `pageLogs` 没有任何 tenant 条件。
2. `tenant_id` 不能让调用方各自传：登录成功、匿名尝试、登出、代登录四种语义不同，散在调用方一定会乱；收进 service 按方法语义决定。
3. `recordLogout` 如果用 `@Async`，ThreadLocal 里的 `LoginCtxDto` 会丢；改成 caller 先取好 `LoginCtxDto + ip` 再传进去。
4. 历史数据不 backfill：开发期老日志只对超管可见，接受这个缺口，不为了历史数据拖慢上线。

## 现在的规矩

- 租户字段的取值语义收在 service，调用方不传 `tenant_id`。
- 分页过滤按 caller 身份分流：null = 看全部；非空 = 只看自家，NULL 行不可见。
- 异步方法不依赖 ThreadLocal，上下文由调用方显式传入。
