# 模板补丁

技能点：[[EasyCode与Velocity]] · 方法：断言式补丁链（待建） · 通用技能：[[工程效率与AI]]

**什么时候会遇到**：模板生成出来的代码「能生成、能编译，但运行期错」，或者配置一改就漂移；需要把一处修复稳定复用到多张表、多个库。

## 判断顺序

1. 先分清是模板错、配置错还是数据/类型映射错；别急着手改生成物。
2. 看错误出现在编译期还是运行期。编译期先修；运行期静默错（跨行改删、NOT NULL、类型转换）优先修。
3. 判断是不是只在一类表上出现：复合主键、分区子表、`inet`/`jsonb`、`is_` 前缀、租户列进主键。
4. 只跑一个库能不能覆盖？不能就多库采样。
5. 改动写成补丁：替换片段 + 断言命中 1 次，不手改最终配置。
6. 跑全链：桩一致性 → 重建配置 → 多库生成编译 → 两道守卫 → 运行期测试。
7. 编译不报的错交给产物守卫；守卫判据从真实 schema/配置取。

## 手段

- **断言式补丁**：`rep()` 统计替换次数，不是 1 次就抛错；补丁链按 fix1…fix9 固定顺序执行（`easycode-sim/fix5.js:7`、`easycode-sim/fix8.js:7`；`easycode-sim/build-config.sh:13-21`）。
- **分层**：fix1–fix3 基础口径，fix4 生成范围，fix5 复合主键，fix6 废 import/重复条件，fix7 重复 import，fix8 跳过清单与文案漂移，fix9 跳过表的主键推导闸门（`easycode-sim/build-config.sh:2-5`；`easycode-sim/report/修复与验证.md:29-36`）。
- **仿真台保真**：复刻全局配置纯字符串替换、Velocity 2.3、`getJavaType`、`format_type` 归一化（`easycode-sim/report/修复与验证.md:113-122`）。
- **多库采样**：五个库一起跑；只跑 message 时 20 处复合主键只覆盖 2 处（`easycode-sim/verify-all.sh:7-9`、`:33-37`）。
- **复合主键守卫**：A 类真复合主键不许标 `@TableId`、Mapper 走 `MuouNoPkMapper`；B 类租户单主键必须从 `scoped()` 起手；C 类单主键不许误伤（`easycode-sim/guard-composite-pk.sh:8-13`、`:91-149`）。
- **产物守卫**：扫 `java.lang` import、重复 import、未使用 import、`updateFull` 的 WHERE 重复/缺条件（`easycode-sim/guard-generated-code.py:3-8`、`:41-66`）。
- **桩与导出物**：标「逐字拷贝」的桩逐字比对；`tpl/` 从配置导出，`--check` 不同步即失败（`easycode-sim/sync-stub.sh:1-6`；`easycode-sim/export-tpl.js:1-9`）。
- **工作区同步**：仿真台配置与 IDEA 用的 `EasyCodeConfig.json` 分开，`--check` 有差异就退出 1（`easycode-sim/sync-workspace-config.py:3-15`）。

## 反例 / 边界

- 手抄模板：当时 21 个导出模板/全局配置里 16 个和真配置对不上，拿它当依据就被骗（`easycode-sim/README.md:27`；`easycode-sim/export-tpl.js:3-4`）。
- 复合主键标了 `@TableId` 照样编译通过，`updateById` / `deleteById` 是静默跨行，改掉别人的数据还不报错（`easycode-sim/guard-composite-pk.sh:4-6`）。
- 只跑一个库：模板的毛病只在一类表上现形，message 库覆盖不到 core 的 `is_default`、billing 的 `is_void`（`easycode-sim/report/修复与验证.md:96-104`）。
- 守卫只扫产物，不扫模板；判据必须和模板同源，否则守卫和生成器各说各话（`easycode-sim/guard-composite-pk.sh:38-42`）。
- 补丁链不是生成器单测：它保证「这一版配置能重建」，不保证「插件在 IDEA 里行为一致」。
- 58 处补丁之后仍有已知坑：敏感列、`is_` 前缀、`inet` 过滤（`easycode-sim/report/修复与验证.md:138-140`）。

## 现在的规矩

1. 不手改 `config/EasyCodeConfig.final.json`；改 `fixN.js` 和 `tpl/patch/` 片段。
2. 每处替换断言命中 1 次；命中数不对直接失败。
3. 改模板必须跑 `verify-all.sh` 全链，`--quick` 只用于迭代。
4. 新守卫的判据从产物/schema/配置取，不从模板注释取。
5. 验证失败先查退出码有没有被管道吞掉（`easycode-sim/report/修复与验证.md:149-150`）。
6. 工作区配置改动走 `sync-workspace-config.py --write`，不手工复制。
