# 单测与集成测试

技能点：[[JUnit与Testcontainers]] · 方法：[[Mock 与真实容器的取舍]] · 通用技能：[[测试与质量]]

**什么时候会遇到**：写完一个 Service/DAO，纠结这个依赖要不要 mock、要不要起 MySQL；或者测试绿了，但不确定它到底证明了什么。

## 判断顺序

1. **被测对象是什么层**：纯逻辑（状态机、计算、分支）→ Mockito；DAO/插件/SQL → 真库；MVC 契约 → `@WebMvcTest`；整条 HTTP 栈 → `@SpringBootTest`。
2. **要证明的行为依赖什么**：依赖真实 SQL 方言、事务、拦截器、序列化、过滤器，就必须起对应真实依赖；只依赖返回值/异常，用替身。
3. **替身会不会替掉被测行为**：如果 mock 掉的就是要验证的规则，测试只剩自我实现。
4. **失败时能不能定位**：断言里写清业务后果；否则红了也不知道是数据、SQL 还是逻辑。
5. **默认构建会不会跑**：命名、Docker、exclude 三件事都会让测试静默不跑。

## 测试数据隔离

- **租户上下文**：`MockHttpServletRequest` + `LoginContext.populate`，每个用例显式设当前租户（`FilesSoftDeleteItTest.java:79-89`）。
- **每个用例自己造行**：DAO `save` 返回自增 id，断言 id 级结果；不依赖别的用例留下的数据（`FilesSoftDeleteItTest.java:91-101`）。
- **库名隔离**：每个测试类用独立 `databaseName`（`FilesSoftDeleteItTest.java:69-72`、`TenantIsolationIT.java:74-77`）。
- **全栈先跑脚本**：`init.sql` + `update-init.sql` 建表，再 seed 用户/角色/权限（`AuthPermissionE2eTest.java:91-130`）。

## 断言：看 body code，不只看 HTTP status

项目统一「HTTP 200 + body code」：404/405/业务错误都是 200（见 [[Spring应用与接口契约]]），只断 `status().isOk()` 等于没断错误类型。

- 正确写法：`status().isOk()` + `jsonPath("$.code").value(404)`（`CoreControllerAdviceNotFoundTest.java:61-65`）。
- 集合断言用完整 `equals`，不用 `contains`：多算和少算都能红（`FilesSoftDeleteItTest.java:142-147`）。

## 反例 / 边界

- **只断 SQL 文本**：能证明「条件写了」，证明不了「结果对」；过度过滤时文本断言照样绿（`FilesSoftDeleteItTest.java:41-44`）。
- **反射守 `@Transactional`**：只证明注解声明了，证明不了 AOP 代理和真实回滚；作者注明这是「退而求其次」（`WarehouseReserveLocationTest.java:363-376`、`WarehouseUploadPhotoTest.java:265-278`）。
- **无 Docker 静默跳过**：`disabledWithoutDocker = true` 在没 Docker 的机器上整类 skip（`FilesSoftDeleteItTest.java:51`）。
- **`*IT.java` 默认不跑**：`pom.xml` 只配了 surefire（`pom.xml:345-355`），全文没有 failsafe；`TenantIsolationIT` 不在 `mvn test` 里。
- **`@WebMvcTest(addFilters=false)`**：Security 过滤器不参与，认证行为证明不了（`CoreControllerAdviceNotFoundTest.java:28-31`）。
- **全栈 E2E 仍不覆盖浏览器**：HTTP 层过了不代表页面能点。

## 现在的规矩

- 涉及软删、租户、分页、SQL 改写、序列化 → 起真库，不 mock DAO；纯分支/状态机 → Mockito，mock 协作方不 mock 被测类。
- 每条断言写清业务后果；正反成对。
- 新测试先确认 surefire 默认会匹配；不会跑的就改名或接 failsafe。
- 测试替身和真实依赖的选择，在测试类注释里写一句「为什么」。
