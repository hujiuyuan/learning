# 租户隔离测试

技能点：[[MyBatis-Plus]] · 项目：smart WMS / muou-client · 2026-09

场景：[[多租户拦截]]、[[平台账号与NULL]]

## 我想干什么

让「租户隔离」有可回归的证据：跨租户不可见、平台账号可见全量、count 与列表同口径、白名单漂移会红，而不是靠代码注释宣称。

## 我干了什么

- **跨租户不可见**：smart `TenantIsolationIT` 用 Testcontainers MySQL 起库，A 租户传 B 的 `tenantId` 参数仍被插件过滤，count 为 0（`smart-server-wms3/src/test/java/com/track/wms/config/TenantIsolationIT.java:104-140`）；`update_crossTenant_affectsZeroRows` / `delete_crossTenant_affectsZeroRows` 断言跨租户写影响 0 行（`TenantIsolationIT.java:272-311,350-395`）；insert 后切租户查不到、切回来能查到（`:240-271`）。同一测试类里另有一条 `updateAcctStatusBySource_crossTenant_updatesAllSiblings`（`:312-349`），是显式跨租户的业务例外，不能当成隔离失败。
- **平台账号全量**：同一 IT 里平台账号（`tenantId=null`）能看到两个租户的数据，并对 14 张业务表逐一 count 确认不报错（`TenantIsolationIT.java:172-235`）。
- **count 同口径**：租户插件注册在分页插件之前，分页生成的 count 也带租户条件（`smart-server-wms3/src/main/java/com/track/wms/config/MybatisPlusConfig.java:36-39`）；页面侧另有 `page.total` 只算本租户的断言（见 [[租户插件落地]]）。
- **白名单漂移**：muou 的 `TenantIgnoreTablesCheck` 断言两个方向——实体没有 `tenantId` 但漏登记、表加了 `tenantId` 但白名单没摘，都会红；`extraIgnored` 写错表名、表已删、或其实没有 `tenant_id` 列也会红（`muou-backend/muou-common/muou-common-app/src/test/java/com/voidtech/muou/common/arch/TenantIgnoreTablesCheckTest.java:23-67`）。
- **检查自己会红**：白名单检查用探针实体逐条证明「登对了不红、漏登记红、过期登记红、包名写错红」（`TenantIgnoreTablesCheckTest.java:12-67`）。
- **默认装配**：断言默认事务管理器是 `TenantAwareTransactionManager`，退化成 Boot 默认等于关掉 RLS，而且不报错（`muou-backend/muou-common/muou-common-app/src/test/java/com/voidtech/muou/common/tx/TxAutoConfigurationTest.java:63-70`）。
- **事务不残留**：受限角色跑完读事务后，新开连接直接查同一张表为 0（`muou-backend/muou-server-member/muou-member-app/src/test/java/com/voidtech/muou/member/form/FormTemplateRlsTest.java:50`）。
- **逃生舱不靠巧合**：`OrphanOccupyItTest` 在带租户登录态的线程里调用全租户扫描，断言 `TenantIgnore` 强制兜底，另一租户的孤儿行仍返回（`smart-server-wms3/src/test/java/com/track/wms/dao/OrphanOccupyItTest.java:47-55`）。

## 犯了什么错 / 误判

1. **只测「查不到」，不测「查得到」**：过度过滤也能让「跨租户不可见」绿灯。要同时断言本租户数据照常返回（`TenantIsolationIT.java:124-132`）。
2. **只用管理员连接测 RLS**：超级用户/表 owner/`BYPASSRLS` 角色会绕过策略，测试全绿但线上没有隔离。测试库要建 `NOSUPERUSER NOBYPASSRLS` 的受限角色（`RestrictedRoleAssertions.java:21,60`）。
3. **只测查询，不测写入**：跨租户 update/delete 如果影响行数不是 0，说明条件没进语句（`TenantIsolationIT.java:272-395`）。
4. **白名单检查只测通过**：检查函数自己写错时，所有用例照样绿灯；所以要给每条失败分支配探针，连「一个实体都没扫到」也单独断言（`TenantIgnoreTablesCheckTest.java:26-67`）。
5. **解析失败路径没有专门用例**：`SafeTenantLineInnerInterceptor` 跳过过滤是已知缺口，但没找到覆盖 `ParseException` 分支的测试。

## 怎么解决

- 每个隔离机制至少三条测试：跨租户不可见、本租户可见、平台/逃生舱可见。
- count 断言与列表断言用同一套 where；插件顺序由配置测试或代码审查锁住。
- 白名单/配置类检查必须自证会红，失败分支逐个覆盖。
- RLS 测试用受限角色和随机临时库，避免本地管理员连接和环境数据掩盖问题。
- 逃生舱测试要把调用方置于「有租户上下文」的场景，证明是 `TenantIgnore` 生效，而不是恰好没有登录态。

## 现在的规矩

- 新表接入租户过滤，至少补一条跨租户 IT。
- 白名单变更必须过架构测试，不接受「先上线再补」。
- RLS 用例默认用受限角色；用管理员连接跑的用例要注明它测的不是策略。
- 不把「测试通过」写成「全仓隔离完成」：覆盖的是被断言到的那几条路径。
