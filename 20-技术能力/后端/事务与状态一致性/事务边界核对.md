# 事务边界核对

技能点：[[Spring事务]] · 通用技能：[[事务与状态一致性]]

**一句话**：先列出一次业务里所有「写」和「外部动作」，把必须同生共死的写圈成一个事务，再把查询、HTTP、文件、消息挪出去；边界定错，后面加多少注解都救不回来。

## 方法总纲

1. **列动作**：这次业务读了什么、写了哪些表、调了哪些外部系统（HTTP/RPC/MQ/S3/邮件）、发了什么异步任务。
2. **圈原子集**：只有「一个失败另一个必须回滚」的数据库写才进同一事务；跨库/跨服务写不能靠本地事务。
3. **定入口**：事务放在 Service 的 public 方法，经 Spring 代理调用；Controller 不写事务，private/同类调用改用 `TransactionTemplate` 或拆 Bean。
4. **定传播**：默认 `REQUIRED`；要独立提交/回滚用 `REQUIRES_NEW`；要部分回滚用 `NESTED`/保存点。
5. **移外部动作**：HTTP/S3/邮件放事务外；必须「提交后做」用 `afterCommit`，回调写库用 `REQUIRES_NEW`；消息用 Outbox 或提交后发送。
6. **验证**：真库失败路径/并发测试，或明确标注「只验证了注解存在」。

## 检查表

| 检查项 | 问什么 | 常见错法 |
| --- | --- | --- |
| 代理 | 调用经过 Spring 代理吗？ | 同类 `this` 调用、private/final 方法 |
| 异常 | 异常抛出去了吗？在回滚范围吗？ | catch 后不回抛、checked 异常没 `rollbackFor` |
| 传播 | 内层要加入还是独立？ | `afterCommit` 里用 `REQUIRED`，内层 commit 变 no-op |
| 外部 IO | HTTP/S3/邮件在事务里吗？ | 外部超时拖住/回滚主事务 |
| 异步 | `@Async`/线程池在事务里吗？ | 异步线程没有事务上下文，失败不回滚 |
| 数据源 | 是否同一个数据源/连接？ | 多数据源、跨库，事务上下文断 |
| 大小 | 事务包了多少行/多少锁？ | 大事务锁久、undo 大、回滚慢 |
| 只读 | `readOnly` 当写保护了吗？ | `readOnly` 只是提示，不禁止写 |

## 判断顺序

1. **先问「哪些写必须一起失败」**：订单 + 明细 + 库存流水通常一起；发短信、写日志、传文件不一起。
2. **再问「失败后业务能接受什么」**：能接受最终一致就走 Outbox/补偿；不能接受才上本地事务/XA。
3. **再看调用链**：事务方法是不是被同类/private/异步调用？是就先修调用方式，别加注解。
4. **最后看验证**：有没有真库回滚测试？没有就标「未验证」，不要把反射断言当回滚证明。

## 反例

- 在 private 方法上加 `@Transactional`：代理拦不到，注解等于注释。
- 同类 `this.save()` 调另一个 `@Transactional` 方法：不走代理，事务不生效。
- 事务里调 HTTP：对方成功、本地回滚，或本地成功、对方失败，两边不一致。
- `afterCommit` 里用 `REQUIRED` 写库：外层已提交，内层加入一个已结束的事务，commit 是 no-op。
- 事务里 `@Async` 写日志：异步线程没有事务，主事务回滚日志还在。
- 一个大事务包 10 万行更新：锁久、undo 大、失败回滚更久，并发直接掉。
