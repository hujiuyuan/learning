# 中间件与异步任务

**一句话**：把耗时工作从请求线程挪走只是起点；真正要定的是六件事——任务生命周期写到哪、满了怎么拒绝、线程从哪来、多副本谁干活、失败了重不重跑、结果谁看得见。

## 一、理论：异步任务的六个固定问题

1. **生命周期**：提交（同步建任务记录、返回 id）→ 执行（异步）→ 终态（成功/失败/超时）→ 查询（轮询）。记录必须先于执行落库，否则进程一挂就查不到。
2. **背压**：上游产任务的速度超过下游消费能力时，必须有明确的拒绝点。拒绝可以阻塞排队、限并发、或直接拒绝；没有上限的队列只是把过载推迟到 OOM。
3. **线程池**：IO 密集用虚拟线程或大池，CPU 密集用固定小池；关键不是池多大，而是边界——队列长度、拒绝策略、停机行为。
4. **分布式锁**：多副本下同一任务只能有一个执行者；锁要带租约或看门狗，否则持锁进程崩了就是死锁。
5. **调度**：单机用 `@Scheduled`，多机用调度中心（XXL-Job 等）。调度只保证「触发」，不保证「只执行一次」。
6. **幂等**：任务可能重复触发、超时重试、人工补跑。幂等要落在数据上（唯一键 / 状态 CAS / 租约），不能靠「应该不会重复」。

## 二、实际使用：我在哪里用过

### smart WMS：异步导出 + @Scheduled

- 导出三段式：`submit` 同步建 `io_record` 返回 id（`ExportServiceImpl.java:85-95`），虚拟线程异步翻页写盘上传 S3（`:114-131`、`:145-175`），前端轮询记录。
- 背压：Redisson 分布式信号量，接纳 = 并发 + 排队，满了返回 `EXPORT_QUEUE_FULL`（`ExportPoolConfig.java:57-71`、`ExportServiceImpl.java:101-112`）。
- 调度：5 个类、8 个 `@Scheduled` 方法（通知、孤儿占用、回填、回收、归档），全部套 Redisson 锁，抢锁失败静默跳过（`OmpTenantBackfillJob.java:51-63`、`IoReaperJob.java:42-52`）。
- 幂等：回填任务靠 `WHERE tenant_id IS NULL` 天然幂等（`OmpTenantBackfillJob.java:77-82`）。

### muou：XXL-Job 执行器

- 调度与执行分离：调度中心管 cron 和日志，执行器只接收并执行 `@XxlJob`（`XxlJobConfig.java:11-33`）。
- 4 个 handler：探针、outbox 投递、文章定时发布、权限投影巡检（`ExecutorProbeJob.java:32`、`OutboxDispatchJob.java:39`、`ArticleScheduleJob.java:36`、`AuthReloadJob.java:44`）。
- 幂等：默认用 `JobRunMarker.claim` 条件占位；outbox 用 `FOR UPDATE SKIP LOCKED` + 租约（`OutboxDispatchJob.java:23-26`）。
- 执行器开关默认关，没部署调度中心的环境不会悄悄接活（`XxlJobConfig.java:52-53`）。

### 通知渠道：APNs/Pushy

路径说明：smart 侧相对 `/Users/hujiuyuan/workspace/voidtech/smart/`，muou 侧相对 `/Users/hujiuyuan/workspace/voidtech/muou-client/muou-backend/`。

- **依赖与认证**：`pushy 0.15.6`（`smart-server-wms3/pom.xml:290-293`）；用 `.p8` token 认证而不是推送证书，`ApnsSigningKey.loadFromInputStream(...teamId,keyId)` 在 `@PostConstruct` 里建一次客户端，生产/开发只切 host（`smart-server-wms3/src/main/java/com/track/wms/service/impl/IOSPushServiceImpl.java:55-88`）。密钥以 Base64 放环境变量，配置类只有 keyId/teamId/bundleId/production 五个字段（`smart-server-wms3/src/main/java/com/track/wms/config/PushProperties.java:7-30`）。
- **发送链路**：通知落库后异步发，先按用户过滤「关掉消息通知」的人，再查活跃设备 token；badge 每次从 DB 实时算未读数，不依赖 APNs 累加（`IOSPushServiceImpl.java:101-170`、`:309-330`）。
- **失败处理**：`BadDeviceToken`/`Unregistered` 把 token 标 `is_active=false`，其它拒收只记日志；没有应用层重试、没有过期时间/优先级/collapse-id（`IOSPushServiceImpl.java:249-283`）。推送是尽力而为，真正的未读状态以库里的通知表为准。
- **轮换边界**：token 认证没有证书到期问题，但换 `.p8`/keyId/teamId 要重启服务（客户端只在启动时建）；代码没有密钥轮换流程，也没有多环境并行 key 的切换。

#### 为什么用 APNs/Pushy，不用 FCM/WebPush

- **候选**：APNs 直连（pushy）、FCM 转发、WebPush、站内轮询。当前客户端是 iOS PDA，APNs 是唯一能直达系统通知栏的通道；FCM 在 iOS 上最终仍走 APNs，多一层 Google 依赖和延迟；WebPush 需要浏览器/PWA，PDA 壳不具备；轮询耗电且做不到后台提醒。
- **代价**：只覆盖 iOS，Android/桌面要另接；没有投递保证，APNs 接受不等于用户看到；应用层不重试，网络抖动就丢这一条；token 失效只能靠回执被动清理。
- **为什么仍选它**：需求就是「PDA 上有新任务要响」，APNs 的直达性和系统集成没有替代；把可靠性放在「通知表 + 未读 badge」上，推送只做提醒，丢了也不影响业务状态。
- **什么时候反悔**：上 Android/多端 → 引入 FCM/厂商推送或统一推送网关；需要送达率/重试/优先级 → 在发送前加 outbox 和重试表，而不是把重试塞进 `whenComplete`；需要静默推送/富媒体 → 补 APNs 的 `apns-push-type`、`mutable-content` 等字段。

### 邮件/测试邮件：Mailpit

- **两条发信路径**：smart 用 Spring Mail 的 `JavaMailSender`，`sendEach` 按收件人逐封组装、一次 transport 会话发完（`smart-server-wms3/pom.xml:61`；`smart-server-wms3/src/main/java/com/track/wms/common/util/MailDispatcher.java:79-130`）。muou notify 不用全局 `spring.mail`，而是按通道从配置构造 `JavaMailSenderImpl`，host/port/认证逐通道取（`muou-server-notify/muou-notify-app/pom.xml:87`；`muou-server-notify/muou-notify-app/src/main/java/com/voidtech/muou/notify/service/MailSender.java:62-86`）。
- **测试邮件开关**：`muou.mailer.real-send` 打开走真实 SMTP，关闭改投 `mailpit` 段的 host/port；默认值故意是 `true`，生产漏配时不能静默改道到假服务器（`muou-server-notify/muou-notify-app/src/main/java/com/voidtech/muou/notify/config/NotifyMailerProperties.java:19-31`、`:57-68`）。
- **Mailpit 编排**：上游镜像 `axllent/mailpit:v1.21`，SMTP 1025 + 界面 8025 都只绑 `127.0.0.1`；`MP_MAX_MESSAGES` 默认 500，界面口令 `MP_UI_AUTH` 在测试服务器必填，内存上限 192m（`muou-app-ops/middleware/mailpit/docker-compose.yml:34-59`）。
- **红线**：这个容器不要求认证，谁连上都能冒充平台发信；界面里是验证码和重置链接，所以端口不能对外（`muou-app-ops/middleware/mailpit/README.md:9-10`、`:34-35`）。

#### 为什么用 Mailpit，不用真实 SMTP/只看日志

- **候选**：真实 SMTP 供应商、Mailpit、GreenMail（进程内假 SMTP）、只打日志。真实 SMTP 会把开发/测试邮件发进真人邮箱并消耗额度；只打日志看不到 HTML 渲染、链接和验证码排版；GreenMail 要嵌进 Java 测试进程，跨语言/手工联调不方便，也没有收件箱界面。
- **代价**：Mailpit 不要求认证、数据在内存、删容器即清空，不能当生产邮件服务；每个开发机/测试环境要多起一个容器；端口绑错就有冒充发信风险。
- **为什么选它**：本机和 e2e 需要「真发出去、能打开看」的收件箱，Mailpit 一个容器同时给 SMTP 和 Web UI，且能通过 `real-send` 开关与生产路径共存。
- **什么时候反悔**：要测真实供应商的退信/速率/送达率 → 用沙箱账号或供应商测试环境；团队不用 Docker → 换 GreenMail 或本地 SMTP；Mailpit 成为共享环境的安全负担 → 只保留在本机，测试服务器改投沙箱。

## 三、归纳：异步任务检查清单

1. **入口**：同步做了什么、异步做了什么？返回给调用方的是 id 还是结果？
2. **记录**：状态有没有落库？状态机有哪些态、谁能改、有没有 from-state CAS？
3. **容量**：并发上限多少、排队上限多少、超出返回什么错误码？
4. **线程**：用什么执行器？队列有界吗？拒绝策略是什么？
5. **上下文**：租户/登录态/语言/traceId 怎么带到异步线程？带不过去会不会越权？
6. **锁**：多副本会不会重复跑？锁有租约吗？抢锁失败是静默还是告警？
7. **幂等**：重复执行会写坏数据吗？靠唯一键、状态 CAS 还是租约？
8. **失败**：异常谁接？记录会停在中间态吗？有没有 reaper？
9. **停机**：关机时在途任务等不等？不等的话残留状态谁清？
10. **可观测**：`updated N rows`、处理条数、耗时进日志了吗？

### 三条红线

- 不要用无界队列：过载只是被推迟，最后一起死。
- 不要用 JVM 内锁/信号量保护多副本共享的下游：N 个副本就是 N 倍配额。
- 不要相信「任务不会重复」：调度中心、重试、人工补跑都会打破它。

## 四、回到理论：为什么这些规则成立

- 异步把「请求成功」和「任务成功」拆成两个事实，所以必须有独立的记录与状态机；否则调用方拿到成功响应却永远等不到文件。
- 背压的本质是让过载在可控的地方暴露：拒绝一个请求，比拖垮 DB/S3 再一起失败便宜。
- 分布式锁解决的是「重复」，不解决「无效」：空转任务有锁也照样每小时扫全表，见 [[定时任务与数据库负载]]。
- 调度中心只保证触发，执行侧必须自己保证幂等；这两层责任不能混。
- 虚拟线程降低的是阻塞成本，不是下游容量；所以线程可以多，许可必须少。

## 五、边界

- 本页的异步导出是「进程内线程池 + 数据库记录」；RocketMQ 在 muou 里用于事件驱动（42 个主代码监听器，Outbox 用 `RocketMqTxMessageTransport` 同步发普通消息），不在导出链路里，见 [[RocketMQ]]。Kafka/RabbitMQ 没有项目证据。
- 没做过异步任务的优先级队列、延迟队列、死信队列。
- 跨服务一致性：生产用 Seata XA（5 个服务、11 个入口），AT/TCC 只在测试。muou 的 outbox 做到「本地事务 + 轮询投递 + RocketMQ 普通消息」，见 `Outbox.md:52`；没做过 RocketMQ 事务消息（半消息），Saga 也没有生产证据。
- Nacos 已用于配置中心/服务注册；Sentinel 有 `SentinelAutoConfiguration` 和 Nacos 规则源接入，但没有生产流控调优和压测经验，见 [[Sentinel]]。可观测性（OTel/日志/链路）见 [[可观测性与OpenTelemetry]]。
- XXL-Job 只做了调度中心 PostgreSQL 适配与执行器接入，没有改调度算法、分片算法。
- 导出关机时在途任务直接放弃是明确写下的已知代价（`ExportPoolConfig.java:36-39`），不是「优雅排空」。
