# 异步导出落地

技能点：[[异步导出]] · 项目：[[smart WMS]] · 2026-06

场景：[[导出背压]]

## 我想干什么

把标准分页查询的导出从「同步查全量、写本地盘、请求里等」改成异步：调用方立刻拿到记录 id，后台翻页写 xlsx、传 S3、回填状态，前端轮询记录列表拿下载链接。

## 我干了什么

- 新建 `ExportService.submit`：主线程抓登录上下文、建 `io_record(PROCESSING)`、拿接纳许可，返回 `recordId`（`ExportServiceImpl.java:85-112`）。
- 工作线程用虚拟线程：翻页取数（`PAGE_SIZE=2000`）→ FastExcel 写临时文件 → 上传 S3 → `markDone`；异常 `markFailed`；临时文件 finally 删除（`:114-131`、`:145-203`）。
- 进度写 Redis（TTL 1 小时），读写失败只 warn，不影响导出（`ExportProgressStore.java:14`、`:32-47`）。
- 设计清单 14 个标准分页导出；当前代码有 20 处 `submit` 调用，另有 Info/Warehouse 动态列导出（`smart/docs/superpowers/specs/2026-06-01-async-export-design.md:228-245`、`InfoServiceImpl.java:7701`、`WarehouseServiceImpl.java:3516`）。
- 后补限流：Redisson 两道可过期信号量，接纳 = 并发 + 排队，执行 = 并发（`ExportPoolConfig.java:41-71`）。
- 再补回收：`IoReaperJob` 每 5 分钟扫 30 分钟没动的 PROCESSING 记录（`IoReaperJob.java:32-63`）。

## 犯了什么错 / 误判

1. **翻页按「本页行数 < PAGE_SIZE」判末页**：某页因过滤或删除少一行，就被误判为最后一页，后续页静默丢失。回归测试造了 2500 条、第一页 1999 条的现场（`ExportServiceImplTest.java:133`）。改成按 `total` 判定 + 空页兜底（`ExportServiceImpl.java:162-169`）。
2. **声明 `ExecutorService` @Bean 打掉了 Boot 的 `applicationTaskExecutor`**：Boot 的 `TaskExecutorConfiguration` 带 `@ConditionalOnMissingBean(Executor.class)`，整体退避后 `spring.task.execution.*` 全失效，`@Async` 悄悄落到无界的 `SimpleAsyncTaskExecutor`（`AsyncConfig.java:11-23`）。补 `AsyncConfig` 显式声明同名 Bean 找回配置（`:33-36`）。
3. **Spring 会推断 `ExecutorService.close()`**：`close()` = `shutdown()` + 无限 `awaitTermination`，会拖死停机链。显式 `destroyMethod="shutdown"`（`ExportPoolConfig.java:31-39`）。
4. **JVM Semaphore 在多副本下失效**：配额变成 N 倍；`RSemaphore` 又不自动归还，节点被杀后配额永久缩水；最终用 `RPermitExpirableSemaphore`（`ExportPoolConfig.java:46-55`）。
5. **异步线程读不到请求上下文**：`currentTenantId()` 返回 null = 平台账号，能看到全部租户，跨租户越权。用 `ScopedValue` 把登录快照带进虚拟线程（`ExportServiceImpl.java:86`、`:118`；`smart/docs/superpowers/specs/2026-06-01-async-export-design.md:197-205`）。
6. **reaper 注释滞后**：`ExportPoolConfig.java:37-39` 还写「io_record 没有 reaper，留后续修」，其实 `IoReaperJob` 已补；以代码为准。

## 怎么解决

- 翻页终止：`total` + 空页双条件，测试锁死。
- 线程池：虚拟线程执行器 + 显式 `shutdown`；`@Async` 用独立 `AsyncConfig` 找回配置。
- 限流：分布式可过期信号量，两次 release 各自兜异常（`ExportServiceImpl.java:123-142`）。
- 上下文：`ScopedValue` 绑定，作用域结束自动解绑。
- 残留记录：`IoReaperJob` + from-state CAS（`IoRecordDaoImpl.java:42-60`）。

## 现在的规矩

- 异步任务先建记录再执行；记录状态按 PROCESSING → 终态演进，reaper 用 from-state CAS 防并发覆盖（`markDone` 目前没有 CAS）。
- 翻页终止看 `total`，同时用空页兜底。
- 多副本限流用 Redis，不用 JVM 内并发工具。
- 声明 `ExecutorService` Bean 必须显式 `destroyMethod`，并检查 `@Async` 是否还有执行器。
- 异步线程必须显式传上下文，不能依赖请求态。
- 注释可能滞后，排查以代码为准。
