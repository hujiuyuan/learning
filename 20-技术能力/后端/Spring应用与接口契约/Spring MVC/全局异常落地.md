# 全局异常落地

技能点：[[Spring MVC]] · 项目：[[smart WMS]] · 2026-08

场景：[[全局异常与统一响应]]

## 我想干什么

让所有接口的失败响应只有一个出口：业务码不丢、前端消息可翻译、未知异常不泄露原文、404/405 不再被兜成 500。

## 我干了什么

- **2026-04 的方案**（`plan/GlobalExHandler与CoreControllerAdvice合并计划.md`，文件 mtime 2026-04-29）指出两个 `@RestControllerAdvice` 同优先级冲突：`BusinessException`、`MethodArgumentNotValidException`、`Exception` 三个重叠，Spring 选哪个不确定（`:5-13`）。方案定 `CoreControllerAdvice` 为主体，吸收 `BindException`/`IllegalArgumentException`/`NPE` 三个 handler，删掉 `GlobalExHandler`，日志从 error 降为 warn（`:38-110`）。
- **当前代码与方案一致**：全仓只剩 `CoreControllerAdvice` 一个 advice，带 12 个 `@ExceptionHandler`；`GlobalExHandler` 已不存在（grep 无结果）。
- **统一响应**：`Result` 增加 `getError()`/`getReason()` 兼容 getter（`Result.java:55-64`），对应方案里前端字段名不匹配的问题（plan `:132-147`）；主字段仍是 `code`/`message`。
- **404/405**：修前不存在的路径被 `Exception.class` 兜成 code=500（`CoreControllerAdviceNotFoundTest.java:25` 注释）；修后加 `NoHandlerFoundException`、`NoResourceFoundException`、`HttpRequestMethodNotSupportedException` 三个 handler，HTTP 仍 200、body code 精确到 404/405（`CoreControllerAdvice.java:72-97`）。
- **异常上抛**：`FilesController` 去掉手写 catch，异常直接抛给 advice（`FilesController.java:117-124` 注释）；`FilesControllerAdviceTest` 用 `@WebMvcTest` 断言响应体里的 code（`:68-84`）。
- **堵自由文本**：`BusinessException` 的 messageCode 为 null 时，handler 退化到 `INTERNAL_ERROR` 的 i18n 文案（`CoreControllerAdvice.java:185-193`）；裸 String 构造器收窄为包内可见（`BusinessException.java:68-83`）。
- **错误码唯一性**：加 `ResultCodeUniquenessTest`，业务码（≥1000）撞号即失败（`:14-56`）。

## 犯了什么错 / 误判

- 两个 advice 并存，以为「都能兜底」，实际 Spring 按 `@Order` 选，同优先级时处理器不确定（plan `:5-13`）。
- controller 手写 `catch (Exception)` 把结构化 code 压成 500，还把 `e.getMessage()` 拼给前端（`FilesControllerAdviceTest.java:33-38` 注释）。
- 异常 message 用自由文本：finding-10 记录在 `BusinessException.java:68-75` 和 `CoreControllerAdvice.java:185-189` 的注释里。
- 错误码手工分段取号，2026-07 一个月撞 4 次号，才加唯一性测试（`ResultCodeUniquenessTest.java:17-22`）。
- 404 最初没单独 handler，被 `Exception` 兜住变成 code 500（`CoreControllerAdviceNotFoundTest.java:25`）。

## 怎么解决

- 合并 advice，按异常类型拆 handler，统一返回 `Result`。
- 业务异常只认 `ResultCode`；detail 只写日志，不进前端消息（`BusinessException.java:39-55`）。
- 响应包装放 `ResponseBodyAdvice`，异常处理放 `@ExceptionHandler`；一个类里两个职责，但边界清楚。
- 用 `@WebMvcTest` 锁「响应体真的带 code」（`FilesControllerAdviceTest.java:42-45`、`:68-84`），不只测 controller 返回值。
- 唯一性用测试守，不靠肉眼（`ResultCodeUniquenessTest.java:35-56`）。

## 现在的规矩

1. 只允许一个 `@RestControllerAdvice`。
2. 业务失败抛 `BusinessException(ResultCode)`；禁止裸 message 构造器进业务代码。
3. controller 不 catch；框架异常交给 advice。
4. 新增异常类型 = 新增 handler + 一条 MockMvc 断言（status + body code）。
5. 新增错误码 → 跑 `ResultCodeUniquenessTest`。
6. HTTP 200 + body code 是现状；改它要前端、网关一起动。
