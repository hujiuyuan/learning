# 审计日志

所属通用技能：[[安全与审计]]

**一句话**：审计只能加、不能改；一行审计必须和它记录的业务动作同事务提交、同事务回滚，搬运靠同一个主键去重。

## 方法总纲

1. **权威行**：本地审计表是权威，日志库是汇总副本；主键只发一次（UUIDv7），两边同一个值。
2. **唯一写入口**：所有业务只经 `AuditWriter`，不直接写表；writer 只有 INSERT。
3. **同事务**：传播用 `REQUIRED`，不是 `REQUIRES_NEW`；再加一道守卫，要求调用时已经存在别人的事务。
4. **信封**：租户/操作人/trace 一律从上下文取，不从入参取；业务只给动作与改前改后。
5. **敏感字段**：审计里只放 `{mask, ref}`，不放明文也不放密文。
6. **启动自检**：表在不在、必需列齐不齐，缺了直接启动失败。
7. **搬运**：`moved_at` 是唯一搬运状态，没有游标表；重跑靠查重兜底。
8. **归档**：见 [[审计归档]]。

## 我会的部分

- **为什么不用 REQUIRES_NEW**：发号器要独立事务保证立刻可见；审计相反，业务回滚审计必须一起滚，否则留下「做过但其实没做成」的假记录（`JdbcAuditWriter.java:17-28`）。
- **`REQUIRED` 的空档**：没有事务时注解会悄悄开一条，业务漏了 `@Transactional` 就留下永远滚不掉的审计；所以写前先确认「这次调用是跟在别人的事务后面」（`JdbcAuditWriter.java:61-66`）。
- **守卫的正确写法**：只判 `isActualTransactionActive()` 不够，`REQUIRED` 进来前已经把事务开好了；要判 `isNewTransaction()`，`TransactionTemplate` 直接开的事务按「别人的」处理（`JdbcAuditWriter.java:91-111`，测试 `JdbcAuditWriterDbTest.java:171-186`）。
- **回滚同滚**：真库测试断言业务抛异常后审计表零行（`JdbcAuditWriterDbTest.java:188-204`）；提交时同落（`:206-218`）。
- **只 INSERT**：SQL 里没有 UPDATE/DELETE；表名走白名单，值全部参数化（`JdbcAuditWriter.java:32-41,50-54`）。
- **信封**：UUIDv7 时序主键（分区键是 occurred_at，随机主键会让写入在索引里跳）、时刻取插入这一刻、租户/操作人从 ContextHolder 取（`AuditEnvelopeBuilder.java:19-26,97-118`）。
- **敏感字段**：审计正文里的值是 `{mask, ref}`，明文与密文都不进审计（`AuditEnvelopeBuilder.java:128-134`）。
- **启动自检**：表或列缺失直接启动失败，并提示该执行哪个建表脚本；缺列会列出缺了哪些（`AuditSchemaSelfCheck.java:13-21,69-80`，测试 `JdbcAuditWriterDbTest.java:220-244`）。
- **搬运幂等**：按 `moved_at IS NULL` 取批，搬完用 `WHERE moved_at IS NULL AND (键) IN (...)` 回填；同一批重跑不会重复搬（`LogMoverService.java:32,163-166,391-398`）。
- **留存读配置**：读 platform 的留存策略，读不到按失败处理，不拿默认 7 年顶替（`RetentionRuleReader.java:24-34,62-71`）。

## 选型与取舍

| 选择 | 为什么 | 代价/失败模式 | 什么时候反悔 |
| --- | --- | --- | --- |
| 同事务 `REQUIRED` 而不是 `REQUIRES_NEW` | 业务回滚审计必须一起滚，避免「做过但其实没做成」的假记录 | 业务漏 `@Transactional` 时审计会单独提交；要用 `isNewTransaction()` 守卫 | 审计需要独立留存（如登录失败）→ 单独事务 + 明确语义 |
| 本地表为权威、日志库为副本 | 本地表和业务同库同事务，强一致；日志库用于检索/汇总 | 两套存储、搬运延迟；搬运失败要幂等重跑 | 审计量极大、检索需求复杂 → 直接写日志平台 + Outbox |
| 同步写而不是异步 | 和业务同生共死，不丢 | 增加业务延迟；审计表故障会拖住业务 | 高频低风险操作 → 异步 + 本地落盘/Outbox |
| 只 INSERT、无 update/delete | 代码层防篡改，权限层再收回 | 没有 WORM/哈希链，DBA 仍可改；防篡改未闭环 | 合规要求防篡改 → 哈希链/对象锁/独立存储 |
| 敏感字段只存 `{mask, ref}` | 审计库不当泄露源；需要时按 ref 回查 | 审计本身看不到原值，取证要额外权限 | 监管要求留原值 → 加密存储 + 严格访问审计 |
| 留存读配置、不设默认 | 留存期是合规决策，默认值会掩盖配置缺失 | 配置服务不可用时审计写入失败 | 有明确法规默认值 → 可设默认并记录来源 |

## 边界

- `operator_name`、`operator_side`、`ip` 三列恒为空：上下文里没有来源（`AuditEnvelopeBuilder.java:28-34,113-118`）。
- 防篡改未实现：没有 WORM、没有哈希链；代码层只保证没有 update/delete 路径。ADR-0013 的 append-only 权限收回是设计输入。
- 搬运器在 notify 服务，覆盖 core/billing/message 六张本地表，不是通用审计平台。
- 审计查询、导出、跨热冷查询本批没看。
- 只做过 PostgreSQL + JdbcTemplate；没做过事件总线/异步审计。
- 归档任务只摘分区、不删除；删除档现在是 `never`。
