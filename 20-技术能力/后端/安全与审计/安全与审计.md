# 安全与审计

**一句话**：敏感数据的安全不靠「记得加密」，靠三条默认路径：落库前变形、明文接触面可枚举、审计只能追加且与业务同生共死。

## 一、理论：五条底线

1. **加密与查重**：带随机 IV 的 AEAD 密文每次都不一样，不能当等值键。要精确查重，必须另建确定性哈希列（规范化 + HMAC + pepper）。密文负责「存」，哈希负责「查」，两列职责不混。
2. **密钥接触面**：密钥只能在密钥提供方和加解密工具里出现；业务代码拿 DEK、用完清零；KEK 不能和密文同库；KEK 版本必须随密文存，错版本直接失败，不许回退重试。
3. **掩码**：展示用的掩码应该落成列或由模板生成，列表页直接取，不解密。运行时「先解密再掩码」会把明文接触面从加密工具扩大到整个列表链路。
4. **审计权威行**：一条审计必须和它记录的业务动作在同一个事务、同一条连接上；只 INSERT；业务回滚审计同滚；调用方没有事务就拒写。
5. **留存分层**：留存年限读平台配置、不写死；归档按整月分区摘除、不逐行删；默认分区永远不碰；摘到冷层就停，DROP 另行定案。

这些规则的共同点：都靠「唯一入口 + 默认生效」。一旦有人自建 KeyProvider、手工 new 审计写入器、绕过实体写裸 SQL，保障就整体失效，所以还要在启动期和测试里守。

## 二、实际使用：muou 的 PII 与审计

- **加密**：`PiiCipher` 用 AES-256-GCM，12 字节随机 IV、128 位认证标签、32 字节 DEK，密文格式 `[IV][密文][TAG]`（`PiiCipher.java:13-32`）。每条数据现取 DEK，由 KEK 包裹后随密文存（`IdNoVault.java:18-22`）。
- **查重**：`PiiHasher` 对「类型码|国籍|归一化号码」做 HMAC-SHA256，pepper 按版本从 KeyProvider 取（`PiiHasher.java:33-96`）；落库是密文列 + 掩码列 + 指纹列三列并存（`V202609112100__core_init.sql:235-237`、注释 `:271-273`）。
- **启动体检**：`KeyProviderGuard` 对容器里每个 KeyProvider 检查环境名、预发/生产拒绝公开测试密钥、包裹解包自检，懒加载的也拉出来查（`KeyProviderGuard.java:47-110`）。
- **审计写入**：`JdbcAuditWriter` 只 INSERT、传播 `REQUIRED`，并守卫「必须跟在已有业务事务后面」（`JdbcAuditWriter.java:17-28,61-66,91-111`）；审计信封里敏感字段只放 `{mask, ref}`（`AuditEnvelopeBuilder.java:128-134`）。
- **审计自检与搬运**：启动自检表与 20 列（`AuditSchemaSelfCheck.java:31-36,69-80`）；本地表到日志库靠同一个 `audit_id`，`moved_at` 是唯一搬运状态（`LogMoverService.java:32,163-166,391-398`）。
- **归档**：整月分区摘除、留存现读、默认分区不碰（`AuditLogArchiveService.java:26-42`）。

## 三、归纳：安全审计检查清单

拿到一个「存敏感数据 + 记审计」的需求，按顺序问：

1. **分级**：哪些字段必须加密？加密列不能模糊搜索/排序，别笼统写「PII 全加密」。
2. **查重**：业务要不要按它精确查重？要就补哈希列；规范化规则、算法、pepper 版本能不能一起存？
3. **密钥**：KEK 和密文是不是同库？错版本会不会静默回退？预发/生产会不会挂到仓库里的测试密钥？
4. **展示**：列表页是从掩码列取，还是「解密后再掩码」？
5. **审计事务**：写入跟业务同一事务吗？`REQUIRED` 自建事务那条路堵了吗？
6. **审计可改性**：代码里有没有 update/delete 路径？搬运是不是只回填 `moved_at`？
7. **留存**：年限读配置吗？读不到是失败还是拿默认值？归档是整分区还是逐行？默认分区碰了吗？DROP 了吗？

### 三条红线

- 不拿 AEAD 密文判重：随机 IV 保证每次密文不同，判重必错。
- 不在预发/生产使用仓库公开测试密钥：启动成功、加密照算、没有告警，等发现时数据已经废了。
- 不让审计脱离业务事务：用 `REQUIRES_NEW` 或允许注解自建事务，都会留下「做过但其实没做成」的假留痕。

## 四、回到理论：为什么这些规则成立

- **随机性换机密性，确定性换可查性**：AEAD 的 IV 必须随机（复用 IV 会泄露明文关系），代价就是密文不可比较；等值查重只能靠另一列确定性哈希。这是不可兼得的取舍，不是实现没写好。
- **事务是业务与留痕之间唯一可靠的绑定**：异步写、独立事务、消息队列都在两者之间开了时间窗；窗内失败就会出现有业务无审计、或有审计无业务。
- **分区是物理操作的最小单位**：逐行 DELETE 产生 WAL 膨胀、锁和误删风险；整月摘除近似 O(1)，且天然对齐「按月留存」的合规口径。
- **配置读不到时的默认值会把事故伪装成正常**：留存年限、密钥版本这类值一旦「猜一个」，错了没人知道；所以宁可启动失败或整轮失败。
- **启动期体检比运行期告警值钱**：密钥错、表缺列到了运行期，第一批数据已经被污染或第一条审计已经丢失。

## 五、边界

- **KMS 未接**：只有文件密钥（`PiiCryptoConfig.java:39-60`），没有轮换流程、没有 KMS 可用性缓存。
- **防篡改未实现**：没有 WORM、没有哈希链；只做了分区摘除，且明确不 DROP（`AuditLogArchiveService.java:39-41`）。ADR-0013 的冷区对象存储是设计输入，不是已上线能力。
- **审计信封不全**：`operator_name`、`operator_side`、`ip` 三列现在恒为空，上下文里没有来源（`AuditEnvelopeBuilder.java:28-34,113-118`）。
- **L2 明文是产品取舍**：手机号/邮箱按 ADR-0009 明文存储（设计输入），不在本页实战范围。
- **范围窄**：只做过应用层加密 + PostgreSQL 按时间分区；没做过 TDE、列级权限、可搜索加密、HSM、跨云归档。
- **敏感访问留痕**有表和搬运（`LogMoverService.java:76-78`），本批没有展开读业务写法。

## 六、Web CSP / 浏览器侧加固

路径相对 `/Users/hujiuyuan/workspace/voidtech/muou-client/muou-frontend/muou-web/`。

- **静态 CSP**：`contentSecurityPolicy()` 在构建时拼一条字符串，经 `headers()` 对全站下发；`default-src 'self'`、`base-uri 'self'`、`object-src 'none'`、`frame-ancestors 'none'`、`form-action 'self'`，脚本/样式按站点实际加载放行（`next.config.ts:21-45`、`:58-75`）。
- **为什么不用 nonce**：Next 官方强 CSP 要在 `proxy.ts` 里逐请求发 nonce，前提是整站动态渲染；muou-web 的三语首页、33 条业务页、文章详情和 sitemap 都靠静态预渲染，为 nonce 把整站改成按请求渲染，代价大于收益（`next.config.ts:7-18`）。
- **代价要写清**：`script-src` 只能带 `'unsafe-inline'`（Next 的 hydration 引导脚本是内联的），这条策略**挡不住内联脚本注入**；它挡住的是外部脚本源、`<base>` 改写、插件对象、iframe 套壳、表单劫持到站外（`next.config.ts:15-18`、`:34`）。
- **配套头**：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy` 默认拒摄像头/麦克风/定位/支付；`poweredByHeader: false` 不白送框架指纹（`next.config.ts:52`、`:63-75`）。
- **边界**：没有 CSP 报告端点（`report-uri`/`report-to`），违规只能在浏览器控制台看；没有 nonce/hash、没有 Trusted Types；Vue 项目（smart 前端）没有做 CSP。HSTS 归 TLS 终结点，不在 Next 层发（`next.config.ts:52-57`）。

**为什么静态 CSP 而不是 nonce**：nonce 的收益是能禁掉内联脚本，代价是整站退化为动态渲染；静态 CSP 的收益是零运行时成本，代价是 `unsafe-inline` 留着内联口子。当前站点的内容是静态预渲染，攻击面主要是第三方资源和点击劫持，不是用户可注入的脚本；等出现用户可控 HTML/富文本渲染，或需要挡住内联注入时，再评估 nonce + 动态渲染。**反悔条件**：页面改成动态渲染、或安全要求必须去掉 `unsafe-inline`。
