# 审计归档

技能点：[[审计日志]] · 方法：整月分区摘除（待建） · 通用技能：[[安全与审计]]

**什么时候会遇到**：日志/审计表按月分区、留存 7 年；到期数据要离开热表，但不能逐行 DELETE，也不能删多。

## 判断顺序

1. **表按月分区了吗**：分区键是不是时间列（`occurred_at` / `accessed_at`）？没有分区先建，再谈归档。
2. **到期判据从哪来**：从分区定义里的区间取，不从分区名反解；名字是人起的，区间才是事实。
3. **留存几年**：从 platform 按对象码现读；读不到按失败处理，不拿默认 7 年顶替。
4. **默认分区碰不碰**：永远不碰。它兜的是漏建月份的写入，摘了等于把当期日志一起摘走。
5. **整月到了吗**：分区区间上界不晚于「当刻所在月往前推留存年数」的月初，才算到期。
6. **摘完删不删**：不 DROP。摘到冷层就停，删除档现在是 `never`，到期清除另行定案。
7. **失败怎么办**：按表隔离、表内按分区隔离；重跑可续，已摘的下一轮不会再出现。
8. **按租户跑吗**：不。日志分区是库级、跨全部租户。

## 手段

- **函数封装**：清单与摘除都走 `log_owner` 的 SECURITY DEFINER 函数，应用角色只有 EXECUTE；函数里再核一遍到期，应用算错也摘不动未到期分区（`LogPartitionMapper.java:10-17,43-57`、`V202610121600__log_partition_archive_functions.sql:59-108`）。
- **父表白名单 + 摘完登记**：函数只认四张日志表；`ALTER TABLE ... DETACH PARTITION` 之后往 `log_archived_partition` 登记一行，权限收回靠那张表（`V202610121600__log_partition_archive_functions.sql:69-71,87-95`）。
- **整月判定**：`cutoffOf` 取当刻所在月往前推 `keepYears × 12` 的月初（Asia/Shanghai），只摘区间整月早于它的分区（`AuditLogArchiveService.java:112-131,159-164`）。
- **默认分区保守判定**：布尔、数字、`'t'` 都认；认不出的一律按默认分区处理，宁可不摘（`AuditLogArchiveService.java:144-157`）。
- **永久档失败**：`keepYears` 为空（永久·不可删除）判不出到期，这一张按失败报，不静默跳过（`AuditLogArchiveService.java:104-110`）。
- **失败隔离**：一张表失败不影响别的表；同表一个分区失败不影响其余到期分区（`AuditLogArchiveService.java:78-91,123-131`）。
- **重跑可续**：清单每轮从系统目录现读「还挂在父表下」的分区，摘掉的下一轮不出现（`AuditLogArchiveService.java:94-100`，测试 `AuditLogArchiveServiceTest.java:181-207`）。
- **测试守住的边界**：默认分区/未到期/区间解析不出的都不碰（`AuditLogArchiveServiceTest.java:76-93`）；`is_default` 不裸转布尔（`:209-226`）。

## 反例 / 边界

- **逐行 DELETE**：WAL 膨胀、锁表、误删；分区表就该整块摘。
- **按分区名反解月份**：名字不规范就判错；区间才是事实。
- **读不到留存用默认值**：合规口径错，而且没人知道。
- **摘默认分区**：当期日志一起走。
- **DROP 到期分区**：不可逆；删除档是 `never` 时不能做。
- 本页的「冷层」是脱离父表后仍在同一库；ADR-0013 说的对象存储冷区、WORM、哈希链都未实现（设计输入，不是已上线能力）。
- 只做过 notify 的四张日志表（`log_audit` / `log_login` / `log_error` / `log_sensitive_access`），没做过跨库/跨云归档。

## 现在的规矩

- 归档只摘分区、不删数据；删除要单独拍板。
- 留存年限永远现读，读不到就整轮失败。
- 默认分区永不碰，认不出的一律当默认。
