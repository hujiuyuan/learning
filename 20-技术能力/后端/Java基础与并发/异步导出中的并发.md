# 异步导出中的并发

技能点：[[Java并发与虚拟线程]] · 项目：[[smart WMS]] · 2026-07

场景：[[线程池与CompletableFuture]]、[[ScopedValue上下文]]

路径约定：以下 `路径:行号` 相对 `smart-server-wms3/src/main/java/com/track/wms/`；测试相对 `smart-server-wms3/src/test/java/com/track/wms/`；配置文件相对 `smart-server-wms3/src/main/resources/`。

## 我想干什么

导出大结果集时不阻塞 HTTP 请求；同时保护 DB/S3 不被多个导出打满；多副本部署下配额一致；前端能看到进度；关机时不要把停机流程拖死。

## 我干了什么

- **同步建记录**：`submit()` 先抓登录上下文快照、落 `io_record`，返回 `recordId`（`service/impl/ExportServiceImpl.java:84-96`）。
- **入口限流**：`exportAdmit.tryAcquire(0, 30, MINUTES)`，拿不到直接 `markFailed` + `EXPORT_QUEUE_FULL`（`:97-112`）；租约 30 分钟，节点被杀后自动归还。
- **异步执行**：`exportExecutor.submit(...)`；worker 内先 `exportRunning.acquire(30, MINUTES)` 排队，再 `ScopedValue.where(...).run(...)` 执行导出（`:114-131`）。
- **翻页写出**：每页 2000 行，按 `total` 判断结束、空页兜底；每页更新 Redis 进度；最后上传 S3 并 `markDone`（`:145-175`）。
- **清理**：`finally` 清进度、删临时文件（`:200-203`）；两个许可各自 `releaseQuiet`，一个失败不连累另一个（`:123-130`、`:136-142`）。
- **兜底**：`IoReaperJob` 每 5 分钟扫 `PROCESSING` 超过 30 分钟的记录并置失败（`scheduler/IoReaperJob.java:31-35`、`:42-64`）。

## 犯了什么错 / 误判

1. **翻页按「本页行数 < PAGE_SIZE」判断末页**：某页有 1 条被过滤时只有 1999 行，会被误判为末页，后续 500 行静默丢失。回归测试 `truncation_bug_pageShortOfPageSize_stillPullsNextPage` 把场景钉死（`service/impl/ExportServiceImplTest.java:127-156`）。
2. **执行器 Bean 让 `@Async` 的自动配置整体退避**：两个 `ExecutorService` Bean 触发 `@ConditionalOnMissingBean(Executor.class)`，Boot 不再产出 `applicationTaskExecutor`，`@Async` 落到无界 `SimpleAsyncTaskExecutor`（或调度线程），yml 里的队列/停机配置全部失效（`config/AsyncConfig.java:8-28`）。
3. **Java 21 的 `ExecutorService.close()` 会无界等待**：Spring 默认推断 `close()`，在途任务不结束就卡住整个 `destroySingletons()`；改为 `destroyMethod = "shutdown"`（`config/ExportPoolConfig.java:31-44`、`config/PoolShutdownTest.java:23-33`）。
4. **Future 无人检查**：`submit()` 的返回值被丢弃，Runnable 内必须自己 catch 并写 `markFailed`，否则失败只在日志里（`service/impl/ExportServiceImpl.java:114-131`、`:197-199`）。
5. **许可 release 也可能抛异常**：Redisson 对已过期租约调 `release` 会抛；如果它连累第二次 release，另一个许可要等租约到期才自愈（`:123-130`）。

## 怎么解决

- 翻页终止改「按 total + 空页兜底」，并加回归测试（`service/impl/ExportServiceImpl.java:154-171`、`service/impl/ExportServiceImplTest.java:162-171`）。
- 用 `AsyncConfig` 显式声明 `applicationTaskExecutor` / `taskExecutor`，用测试断言真实线程名前缀 `task-`（`config/AsyncConfig.java:33-36`、`config/GracefulShutdownTest.java:88-104`）。
- 执行器销毁显式 `shutdown`，用测试断言销毁 1 秒内返回（`config/PoolShutdownTest.java:63-94`）。
- 两个许可各自 try/catch 的 `releaseQuiet`（`service/impl/ExportServiceImpl.java:136-142`）。
- 节点丢失留下的 `PROCESSING` 由 `IoReaperJob` 30 分钟兜底（`scheduler/IoReaperJob.java:17-32`）。注意：`ExportPoolConfig` 的类注释仍写「当前没有 reaper」，与 `IoReaperJob` 的存在矛盾，属于注释过时。

## 现在的规矩

- 异步任务入口：先落状态记录，再抢 admit 许可，再 submit；三步顺序不能反。
- worker 内先抢 running 许可，再包 ScopedValue；`finally` 必须两个许可都释放。
- 所有异常在 worker 内闭环成 `markFailed`，不依赖 Future。
- 停机接受「在途导出被放弃」，靠状态表 + reaper 兜底；不为了不丢任务把 shutdown 改成无限等待。
- 虚拟线程数不设上限，真正的上限在信号量；下游配额变化只改 `export.concurrency/queue`。
