# 权限模型迁移

技能点：[[Spring Security]] · 项目：[[smart WMS]] · 2026-05

场景：[[权限模型]]、[[RBAC权限模型]]

时间说明：`smart` 不是 git 仓库，2026-05 按计划文档日期和文件时间推断，不是提交记录。

## 我想干什么

把「角色能看什么、能用什么、能授什么」拆开：

- 角色列表不能把平台角色泄露给子公司；
- 权限管理员可以分配业务权限，但自己不一定能操作业务；
- 复制角色不能把调用者没有的权限带过去；
- 超管也不要靠代码 bypass，统一走权限表。

## 我干了什么

- **加列**：`sys_role.scope` 表示可见性位图；`sys_role_permission.can_use/can_grant` 拆开「能用/能授」（`update-init.sql:54,69-70`）。
- **枚举**：`SysScopeEnum` 用 `PLATFORM=1 / SUBSIDIARY=2 / COMMON=3`，SQL 按位与过滤（`SysScopeEnum.java:36-50`）。
- **角色列表**：子公司 caller 只看 `(scope & 2) > 0` 且属于本租户或系统级的角色（`SysRoleMapper.xml:19-28`）。
- **调用者封顶**：`grantablePermIds` 取 caller 角色的 `can_grant=1` 并集（`SysRolePermDaoImpl.java:62-72`）；`assertGrantable` 在写库前校验（`SysRoleServiceImpl.java:304-314`）。
- **复制裁剪**：`listCopyable` 过滤超出天花板的角色，`roleTemplate` 对模板权限取交集（`SysRoleServiceImpl.java:236-302`）。
- **权限树**：只查 caller 可授的权限，再按 `parentId` 组树（`SysPermServiceImpl.java:30-48`）。
- **种子**：所有角色（含 `SUPER_ADMIN`）都显式绑 `sys_role_permission`，超管只绑平台集（`seed_permissions.sql:9-13,250-268`）。

## 犯了什么错 / 误判

- **把计划当代码**：计划写「`SUPER_ADMIN` 每次启动自动全表绑定」，但 `UserInitRunner` 已改成不再自动绑定，改由 `seed_permissions.sql` 显式绑平台集（`UserInitRunner.java:25-29`）。照计划写就会把已废弃的 bypass 说成现状。
- **角色数量对不上**：第一版计划 5 个内置角色，后来改成 7 个；旧文档里的角色清单不能直接引用。
- **把 scope 当数据权限**：`scope` 只决定角色对哪侧可见，不决定数据行；租户隔离仍靠 `tenant_id` 查询条件。
- **只做「能用」不做「能授」**：最初权限管理员要么自己能用业务，要么不能分发；拆成 `can_use/can_grant` 后才解决。
- **复制不裁剪**：平台账号复制子公司角色时会把平台权限带过去；用 caller 的 `can_grant` 集合封顶后才收住。
- **先写库后校验**：创建角色时先 INSERT 再校验权限，失败会留半条数据；后来把 `assertGrantable` 前置到任何 DB 写之前（`SysRoleServiceImpl.java:105-108`）。

## 怎么解决

- 以代码和种子 SQL 为准，不照计划复选框写结论。
- 可见性、生命周期、归属分成三列：`scope` / `type` / `tenant_id`，各管一件事（`SysScopeEnum.java:18-23`）。
- 所有「授予」路径统一走 `can_grant` 天花板：创建、更新、复制模板、权限树。
- 自定义角色写入时固定 `can_use=1, can_grant=0`（`SysRoleServiceImpl.java:316-325`），分发权不传染。
- 用单测覆盖：越权提交在写库前抛（`SysRoleServiceImplTest.java:177,196`）、复制为空/部分/全交集（`:219,239,254,269`）、跨租户和平台角色拒绝（`:299,310`）、权限树按 caller 角色查（`SysPermServiceImplTest.java:50`）。

## 现在的规矩

- 角色可见性看 `scope`，不看 `type` 或 `tenant_id`。
- 「能用」和「能授」分开判；授予路径必须有 ceiling。
- 校验放在任何写库之前。
- 超管也不写 bypass，权限一律走表。
- 计划文档只当设计输入，落地结论以代码/测试/种子 SQL 为准。
