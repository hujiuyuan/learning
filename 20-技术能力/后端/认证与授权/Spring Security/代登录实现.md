# 代登录实现

技能点：[[Spring Security]] · 项目：[[smart WMS]] · 2026-05

场景：[[登录态与踢线]]、[[权限模型]]

## 我想干什么

平台管理员不共享子公司账号密码，直接以子公司主账号身份操作；随时能回到自己身份；全程留下可追溯的审计记录。

## 我干了什么

- **start**：校验 caller 是 `SUPER_ADMIN` 或 `PLATFORM_ADMIN`；target 必须是启用中的子公司超管、租户可用、不能是自己；把 admin 的 refresh 轮换成带 `impTarget` 的新 jti；签 `subject=target`、`actor*=admin`、带 `actorKeyVer` 的 access token；维护 `target → [admin_jti]` 反向映射；写 `IMP_ACTIVE`。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:70-143`
- **stop**：签回 admin 自己的 access token，refresh 的 `impTarget` 清空，删 `IMP_ACTIVE`，补 stop 审计。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:193-235`
- **refresh**：`buildImpDto` 每次续期都重新校验 actor 平台角色和 target 有效性；target 失效时回退 admin 视角。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:251-298`、`smart-server-wms3/src/main/java/com/track/wms/service/impl/AuthServiceImpl.java:334-344`
- **过滤器**：effective user 的 keyVer 必查；带 `actorUserId` 时严格比对 actor keyVer；impersonate token 不做单端登录槽比对。证据：`smart-server-wms3/src/main/java/com/track/wms/config/JwtSecurityFilter.java:103-138`、`smart-server-wms3/src/main/java/com/track/wms/config/JwtSecurityFilter.java:245-259`
- **目标清单**：`listTargets` 在 Service 层再查一次平台角色，因为接口级权限开关关闭、controller 没有屏障。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:237-248`

## 犯了什么错 / 误判

1. **只校验被扮演者的 keyVer**：target 自己重新登录或改密，admin 的代登录 token 会被一起踢。现在 actor、effective 两个 keyVer 都校验，并按踢线原因区分是否踢 impersonator。证据：`smart-server-wms3/src/main/java/com/track/wms/common/enums/KickReasonEnum.java:37-42`、`smart-server-wms3/src/test/java/com/track/wms/config/JwtSecurityFilterTest.java:79-127`
2. **refresh 路径硬编码 WMS**：PDA 端发起的代登录续期会读错 keyVer 键，直接 5008。现在 loginSys 从 RefreshVal 透传，键读同一路。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:269-272`
3. **target keyVer TTL 到期**：被扮演账号长期不自己登录，`USER_KEY` 过期后读回 0，产生偶发 `KEY_VER_MISMATCH` 误踢。现在 refresh 时顺手续期 target keyVer TTL。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:273-279`
4. **只在 start 校验资格**：签发后被撤销平台角色的 admin 可以靠 refresh 无限续命；现在每次 refresh 重查平台角色。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:252-261`（代码路径，无专项测试）。
5. **轮换 refresh 留墓碑**：同一会话换视角时裸删旧 jti 会留下「你被踢了」的墓碑，重试收到错误提示；现在轮换只删 token，不留墓碑。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:415-432`
6. **审计 IP 可伪造**：原来直接取 `X-Forwarded-For` 首段，任何调用方都能自填；现在统一走 `ClientIpResolver`。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:453-460`（代码路径，无专项测试）。

## 怎么解决

- 身份拆成 effective（被扮演者）和 actor（真实管理员）两套，token 同时带 `keyVer` 和 `actorKeyVer`。
- actor 校验 fail-closed：Redis 异常、缺 `actorKeyVer`、值不匹配一律拒绝；effective 校验保留 DB 状态兜底。
- 资格判断每次入口都重查，不信任签发时的一次性结论。
- 审计日志的 `tenant_id` 固定 `null`（平台级操作），业务 ID 用稳定的 companyCode，不用公司真名。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:161-174`

## 现在的规矩

- 代登录资格只认平台角色（`SUPER_ADMIN` / `PLATFORM_ADMIN`），子公司账号一律拒绝。
- target 必须是启用中的子公司超管；target 自己、当前 effective、停用或删除的租户都拒绝。
- impersonate token 不抢 target 的 `LOGIN_REFRESH` 槽；target 本人登录或改密不踢管理员。
- 只有撤销类原因（账号禁用/删除、租户禁用/删除）才踢 impersonator；`OTHER_DEVICE`、`PASSWORD_RESET`、裸 keyVer 变动都豁免。
- 每次 refresh 都重查 actor 资格；target 失效则降级回 admin，不阻断刷新。
- 审计必须记录 actor、target、IP；IP 只能来自统一解析器。
