# 认证与授权

**一句话**：认证回答「你是谁」，授权回答「你能做什么」；先有可信身份，再按最小权限逐层判断接口、功能和数据范围。

## 一、理论：五件事

1. **认证 vs 授权**：认证校验凭证并建立会话；授权在每次访问时判断主体能否对资源执行动作。认证失败是 401，授权失败是 403。
2. **Session vs Token**：Session 把状态放服务端，靠 cookie 引用；Token 把身份签进凭证，服务端无状态。Token 的代价是「签发后无法自然失效」，必须另设版本号、黑名单或短过期来撤销。
3. **RBAC vs ABAC**：RBAC 按角色授权，简单、可审计，但难表达「同角色不同数据范围」；ABAC 按属性（租户、部门、资源归属）判断，灵活但规则分散。多数业务系统是 RBAC 打底，数据范围用属性过滤补。
4. **最小权限**：默认拒绝，白名单显式放行；权限按「能用」和「能授」拆开，管理角色不应顺带获得业务操作权。
5. **租户隔离**：多租户下，身份里的 tenant 必须进入每一次数据查询；平台账号（tenant=null）和子公司账号走不同分支，不能靠前端传参决定看谁的数据。

顺序不能反：先认证拿到可信身份，再拿身份去授权；把授权判断交给请求参数或前端，等于没有授权。

## 二、实际使用：我在哪里用过

[[smart WMS]] 的认证授权链路：

- **认证入口**：`SecurityFilterChain` 关闭 CSRF、设为 `STATELESS`，公开路径 `permitAll`，其余 `authenticated`，JWT 过滤器放在 `UsernamePasswordAuthenticationFilter` 之前。证据：`smart-server-wms3/src/main/java/com/track/wms/config/SecurityConfig.java:47-67`
- **JWT 校验**：解析 Bearer token 后依次校验 keyVer、单端登录、账号状态，再把 `LoginCtxDto` 同时写进请求上下文和 `SecurityContextHolder`。证据：`smart-server-wms3/src/main/java/com/track/wms/config/JwtSecurityFilter.java:103-185`
- **撤销机制**：登录、改密、禁用、删除分别 bump 或删除 Redis 里的 keyVer，并写踢线原因；token 里的版本与 Redis 不一致即失效。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/UserServiceImpl.java:857-887`、`smart-server-wms3/src/main/java/com/track/wms/service/impl/UserServiceImpl.java:908-940`
- **接口授权**：`ApiPermFilter` 用 `apiPerms` 做 URL 匹配；方法级 `PermEvaluator` 已装配，等待 `@PreAuthorize` 使用。证据：`smart-server-wms3/src/main/java/com/track/wms/config/ApiPermFilter.java:43-89`、`smart-server-wms3/src/main/java/com/track/wms/config/PermEvaluator.java:16-29`
- **权限模型**：`sys_role.scope` 管角色可见性，`sys_role_permission.can_use/can_grant` 拆开「自己能用」和「能授给别人」。证据：`smart-server-wms3/src/main/resources/db/sql/update-init.sql:54`、`smart-server-wms3/src/main/resources/db/sql/update-init.sql:69-70`
- **代登录**：token 同时带 effective user 和 actor 两套身份，校验被扮演者和操作者两个 keyVer。证据：`smart-server-wms3/src/main/java/com/track/wms/service/impl/ImpersonateServiceImpl.java:105-119`、`smart-server-wms3/src/main/java/com/track/wms/config/JwtSecurityFilter.java:245-259`
- **租户隔离（设计）**：登录日志按 caller tenant 过滤的方案见 [[登录日志租户隔离]]；租户字段的通用坑见 [[租户字段与查询过滤]]。

### muou：Casbin 域内 RBAC（新栈）

路径说明：以下 muou 路径相对 `/Users/hujiuyuan/workspace/voidtech/muou-client/muou-backend/`。简称：`SyncedCasbinDecider.java` = `muou-common/muou-common-app/src/main/java/com/voidtech/muou/common/authz/casbin/SyncedCasbinDecider.java`；`IamPolicyAdapter.java` = 同目录同名文件；`MuouAuthzAutoConfiguration.java` 与 `MuouAuthzProperties.java` = `muou-common/muou-common-app/src/main/java/com/voidtech/muou/common/authz/` 下同名文件；`00-14...` = `muou-app-doc/design/00-技术选型（selection）/00-14-权限判定组件技术选型.md`。

- **模型是四元判定**：`r = sub, dom, obj, act`，`p = sub, dom, obj, act`，角色分组 `g = _, _, _` 三个下划线表示「按域生效」——甲租户的岗位不会放行乙租户的人；`keyMatch(r.obj, p.obj)` 让权限登记表可以写路由模式或结尾通配，`act` 取 HTTP 方法或 `*`（`muou-client/muou-backend/muou-common/muou-common-app/src/main/resources/authz/domain-rbac-model.conf:1-29`）。
- **默认拒绝**：没有任何 `p` 行放行就是不放行；判定四元组缺一个（主体/域/客体/动作为空）直接 `DENY`，不查执行器（`SyncedCasbinDecider.java:62-68`）。
- **必须是 `SyncedEnforcer`**：裸执行器重载是「清空 → 逐行插入 → 重建角色链接」，全程无锁；岗位写入后触发全量重载的几十毫秒里，别的线程会读到半重建模型，表现为偶发 403/菜单空白、刷新就好、日志无异常。换回裸执行器单线程测试全绿，只有按源码扫包名才能拦住（`muou-client/muou-backend/muou-common/muou-common-app/src/main/java/com/voidtech/muou/common/authz/casbin/SyncedCasbinDecider.java:14-23`、`:83-89`）。
- **快照过期即拒绝**：判定先看 `SnapshotFreshness`，过期或从未装载就返回 `UNAVAILABLE`，不去问执行器——问它只会得到「没有规则放行」，与真的没权限在监控上分不开；默认 TTL 30 秒（`SyncedCasbinDecider.java:56-80`；`MuouAuthzProperties.java:29-30`；`muou-common/muou-common-app/src/main/java/com/voidtech/muou/common/authz/SnapshotFreshness.java:20`）。
- **策略表是只读投影**：适配器只从身份服务的分发接口取快照，四个写方法（`savePolicy/addPolicy/removePolicy/removeFilteredPolicy`）一律抛 `AUTHZ_POLICY_WRITE_UNSUPPORTED`；唯一写入处是 iam 的岗位/任职/授权等业务接口在同事务里重建 `iam_casbin_rule`（`IamPolicyAdapter.java:16-26`、`:79-101`）。
- **取数失败用上一份补回去再抛**：执行器装载顺序是「先清空模型、再调适配器、最后重建角色链接」；取数失败会让模型停在清空后的状态，所有判定被拒。适配器把 `lastLoaded` 那一份灌回去再抛，上层不推进新鲜度锚点，过期窗口一过整体拒绝（`IamPolicyAdapter.java:44-71`）。
- **拦截器在公共库最后一个环**：`MuouAuthzAutoConfiguration` 装 `PermissionInterceptor`，顺序在限流、会话、改密、模块门控之后；业务代码里不出现 Casbin 类型（`MuouAuthzAutoConfiguration.java:30-47`、`:134`；`00-14-权限判定组件技术选型.md:96-98`）。

#### 选型与取舍：为什么 jCasbin，不用 Spring Security/OPA/自写

| 方案 | 加权分 | 优势 | 代价 | 项目里的位置 |
| --- | ---: | --- | --- | --- |
| jCasbin 1.82.0 带域模型 | 4.55 | 四元判定 + 主体分组 + 域隔离全由组件做；进程内零网络跳；策略表只读投影 | 判定耗时随策略行数线性劣化；适配器/失效广播要自己写 | 选定 |
| Spring Security 方法级授权 | 3.10 | 零新增依赖 | 判定逻辑全自己写；没有域概念；请求级授权早于路由匹配，取不到路由模式 | 未选 |
| OPA | 2.00 | 哈希查找、规模无关、判定最快 | 多 8 个边车或 1 个全站单点；策略语言零经验；真理源要搬过去 | 未选 |
| 自写岗位表判定器 | 3.55 | 零依赖、哈希查找、规模无关 | 路径通配/分组/域/匹配全自己写，写错方向是多放行 | 未选 |

决策驱动因素里「判定逻辑归谁写」和「真理源唯一性」各占 25%：jCasbin 把路径通配、主体分组、域比对全做完，且策略表只读；Spring Security 只给挂载点，OPA 把真理源搬到自己的进程，自写则要自己实现全部匹配。规模是 jCasbin 唯一的低分项（3400 行 p50 0.12ms、34000 行 2.09ms、190000 行 14.29ms），项目用「只分发本服务关心的那部分策略」把行数压到约八分之一（`00-14-权限判定组件技术选型.md:25-35`、`:60-67`、`:110-118`）。

什么条件下反悔：策略行数/租户数涨到分片也压不住线性劣化 → 评估 OPA/自写哈希判定；需要 ABAC/属性策略 → 当前模型只有域内 RBAC，要换模型而不是换组件；团队不愿维护自写适配器/失效广播 → 回到 Spring Security + 自写判定，但域隔离要自己补。

## 三、归纳：认证授权检查清单

1. **先确认身份来源**：token 怎么签、怎么验、过期怎么办、密钥放哪。
2. **认证要查三件事**：凭证是否有效、会话是否被撤销（版本/单端）、账号是否仍可用（状态/租户）。
3. **授权分三层**：接口级（URL/方法）、功能级（菜单/按钮）、数据级（租户/行归属）。三层都要有，缺一层就有越权口子。
4. **默认拒绝**：公开路径显式列白名单；权限集合为空时拒绝，不是放行。
5. **撤销要有版本号**：只靠 token 过期，改密、禁用、踢线都做不到即时生效。
6. **权限模型拆「能用/能授」**：能操作业务的人不一定能分配权限；能分配权限的人不一定要能操作业务。
7. **租户进查询**：每个列表、详情、导出都要带 caller tenant；平台账号 null 单独分支。
8. **开关和注解要落到证据**：配置里开关是否打开、代码里注解是否真的使用、测试是否覆盖 401/403。
9. **审计身份用 actor**：代登录、切换身份时，业务身份和真实操作人要分开记录。
10. **改动后用 E2E 回归**：至少覆盖「有权限 200」「无权限 403」「未登录 401」三条路径，别只测 happy path。

## 四、回到理论：这些规则背后的原理

- Token 无状态的优点是横向扩展，缺点是**不能撤回**；keyVer 是「服务端版本 + 客户端携带旧版本」的折中，本质是把撤销状态放在 Redis。
- RBAC 的粒度是角色，不是数据；所以**租户隔离不能靠角色**，必须靠查询条件或数据权限。
- 最小权限不仅是「少给权限」，还包括**权限的传递方向**：`can_grant` 限制的是「能把什么授出去」，不是「自己能做什么」。
- 401 和 403 分开，是为了让客户端知道「该重新登录」还是「登录了但没权限」。
- 这些原理与语言、框架无关；Spring Security 只是把过滤器链和表达式求值器提供了出来。

## 五、边界

- 没做过 OAuth2 / OIDC / SSO / 社交登录；授权模型做过 Casbin 域内 RBAC（`SyncedCasbinDecider.java:24`、`DomainRbacModel.java:19`），没做过 ABAC 规则引擎。
- smart WMS 里没做过行级数据权限（RLS）；这里的租户隔离是查询条件级别，不是数据库强制。
- smart WMS 仓库配置里的接口级授权开关是关闭的（`smart-server-wms3/src/main/resources/application.yml:183` 为 `api-perm-enabled: false`），全项目零 `@PreAuthorize`；本页描述的是**代码具备的能力**，不是生产已生效的授权。
- 没做过高并发下的权限缓存一致性专项；Redis 不可用时 keyVer、单端登录校验会降级放过，属于已知取舍。
