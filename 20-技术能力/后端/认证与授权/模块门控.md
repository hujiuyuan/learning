# 模块门控

技能点：[[认证与授权]] · 方法：三条件判据

**什么时候会遇到**：套餐分档、模块分期上线、平台临时关停某模块；网关、套餐页、权限树、后台导航都要对「这个模块现在能不能用」给出一致答案。

## 判断顺序

1. **判据只留一处**：模块能不能用由 platform 一处算，其他端只消费结论。每个端各写一份，改档位或改期次后就会一边放行、一边拦住，而且不报错。
2. **先判期次**：模块登记的 `phase` 不是当前期次（`phase_1`）→ `phase_not_ready`。二期/三期模块即使档位够也不放行。
3. **再判平台开关**：`enabled` 不为真 → `module_disabled`。平台运营端可以单独关掉一个模块。
4. **最后判档位**：模块要求的最低档位序大于本租户当前档位序 → `plan_too_low`。比较用档位序（rank），不用档位名；名字可以改，按名字比会在某次改名后整体失效而不报错。
5. **原因码顺序写死**：`phase_not_ready → module_disabled → plan_too_low`。既没到二期又被平台关掉的行，应该说「N 期开放」，说「平台关闭」会让人以为期次已经到了。
6. **前端只展示、不重判**：后台导航拿到 `available` + `lockedReason`，只负责置灰、拦截页和文案；把判据抄一份到前端，迟早分叉。
7. **读不到门控不得静默放行**：iam 或前端取不到门控结果时，不能把 `gateBlocked` 当 `false`，否则会「置灰了却还能勾」。

## 手段

- **三条件收成一个函数**：`PlatModuleGateConstants.lockReason(gate, currentRank, minPlanRank)` 依次判期次、开关、档位；`available(...)` 等价于 `lockReason(...) == null`（`muou-platform-app/src/main/java/com/voidtech/muou/platform/constant/plan/PlatModuleGateConstants.java:70-97`）。
- **精确原因与粗状态分开**：行结构同时给 `available`（布尔）、`lockedReason`（精确原因码）、`stateLabel`（可用/暂未开放）。粗状态给列表，精确原因给拦截页文案（`ModuleGateRow.java:18-36`）。
- **四个读面同源**：套餐页模块表 `API-12-039`、总会端导航 `API-12-083`、服务间 `API-12-062`、可用模块数 `API-12-054` 都调同一个判定；属会端 `API-12-003` 是另一套五门（多 `coop_missing`、`quota_exceeded`、`dependency_unavailable`），不能混成一个口径（`muou-app-doc/design/12-平台与租户（platform）/12-07-对外接口清单.md:1166`、`:1517-1524`、`:1703`）。
- **网关按路径映射模块**：网关按最长前缀把请求路径归到模块，再问 platform 这个租户开没开通；路径表里没登记的路径放行，所以只登记能确定归属的路径（[[Spring Cloud Gateway]]）。
- **后台导航**：拦截页 `ModuleGateBox` 按 `lockedReason` 渲染原因；菜单置灰不隐藏，模块取数失败不冒充「无数据」（`muou-admin/src/layout/components/ModuleGateBox.tsx:21-42`）。
- **运营端维护**：写口迁到运营端，改 `enabled` 必须带原因，写审计动作 `module_gate.toggle_enabled`，入参校验重复编码（`muou-platform-app/.../OpsModuleGateApiPaths.java`、`PlatformModuleGatePageService.java`）。

## 反例 / 边界

- **判据复制到前端或各服务**：分叉时的表现是「这一端放行、那一端拦住」，不报错，只能靠人发现。
- **按档位名比较**：档位改一次名，门控整体失效。
- **只判 `enabled`**：漏掉期次与档位，二期模块会提前开放，低档租户能看到高档功能。
- **读不到就当可用**：等于把门控失效转成越权放行。
- **把 `039/083/062/054` 与 `003` 混写**：前三者是三条件，属会端五门另算；五门里的 `coop_missing` 要跨 member 判协同关系。
- **六档原因码不等于都产生了**：本判定只产生 `phase_not_ready / module_disabled / plan_too_low`，`quota_exceeded / coop_missing / dependency_unavailable` 是保留码位。

## 现在的规矩

- 模块可用性只在 platform 判一次；调用方与前端只消费结论。
- 原因码顺序固定：期次 → 平台开关 → 档位。
- 档位比较用 rank，不用名字。
- 门控读不到就阻断，不静默放行。
- 运营端改开关必须带原因并落审计。
