# 多租户拦截

技能点：[[MyBatis-Plus]] · 方法：[[插件链]] · 通用技能：[[数据访问与ORM]]

**什么时候会遇到**：要给业务表统一加租户过滤；平台账号要能看全量；JOIN 和复杂 XML 里过滤失效或列歧义。

## 判断顺序

1. **当前 caller 租户是否为空**：为空 = 平台模式，全部表跳过（`WmsTenantLineHandler.java:99`）。
2. **表在全局清单吗**：在 = 不追加租户条件（`:35-83`）。
3. **SQL 能被 JSqlParser 解析吗**：解析失败 = 跳过过滤，只留 warn（`SafeTenantLineInnerInterceptor.java:33-39`）。
4. **是 XML 裸 SQL 吗**：插件会尝试改写，但复杂 JOIN 常常手写条件更可靠，需单独核对（`GoodsMapper.xml:14-27`）。
5. **结果要跨租户吗**：必须 `TenantIgnore.call`，且上游已完成归属/范围校验（`TenantIgnore.java:11-15`）。

## 手段

- **四拦截器顺序**：租户 → 分页 → 乐观锁 → 防全表更新（`MybatisPlusConfig.java:36-48`）。租户在分页前，分页自动生成的 count 才会带租户条件。
- **全局表清单**分三类：无 `tenant_id` 列（`user`、权限/通知/字典表）；有列但需跨租户（`wms_user`、`sys_role`、`operation_log`、`login_log`）；无列但通过父表隔离（`work_task_preload` 等，`:54-58`）。
- **平台账号 `tenant_id IS NULL`**：平台模式全部跳过；平台账号查询在 SQL 里显式写 `tenant_id IS NULL`（`UserMapper.xml:50-58`），通知表用 `tenant_id = ? OR tenant_id IS NULL`（`NotificationMapper.xml:44`）。
- **JOIN 列歧义**：`fba_carrier` 有 `tenant_id` 且 DAO 已全局 `eq`，加入跳过清单，避免 JOIN 后同列被追加两次/歧义（`WmsTenantLineHandler.java:80-82`；测试 `WmsTenantLineHandlerTest.java:57`）。
- **表名归一化**：JSqlParser 保留反引号和原始大小写，匹配前剥离反引号并小写（`WmsTenantLineHandler.java:100-107`；测试 `WmsTenantLineHandlerTest.java:104-121`）。
- **逃生舱**：`TenantIgnore.call` 临时关租户，`finally` 无条件恢复（`TenantIgnore.java:30-36`）；全仓 38 处调用。

## 反例 / 边界

- **解析失败静默跳过**：JSON `->` 等 MySQL 特有语法解析不了时，请求继续但这次查询没有租户过滤（`SafeTenantLineInnerInterceptor.java:16-19, 33-39`）。
- **严格 `eq` 会打空 NULL 行**：`goods.tenant_id` 99.98% 为 NULL，插件注入 `tenant_id = ?` 会把结果清零；调用方只能 `TenantIgnore` 后手写 `(g.tenant_id = ? OR g.tenant_id IS NULL)`（`GoodsMapper.xml:14-27`；报告 `docs/2026-07-16-测试数据库卡顿排查报告.md:82-97`）。
- **存量手动过滤仍在**：类注释承认存量 DAO 有大量手动 `eq("tenant_id")`，插件上线后只是冗余条件，不是全覆盖证明（`WmsTenantLineHandler.java:21-23`）；27 个 mapper XML 里 16 个仍写 `tenant_id =` 过滤条件。
- **子表靠父表间接隔离**：父表过滤漏了，子表就漏（`work_task_preload` 等，`:54-58`）。
- **不能宣称全仓隔离完成**：复杂 JOIN 仍是 XML 裸 SQL，插件覆盖的只是它能改写的那部分语句。

## 现在的规矩

- 新业务表有 `tenant_id` 就不进全局清单；没有列或确需跨租户才进。
- 跨租户读取只用 `TenantIgnore.call`，禁止调用方手写 `InterceptorIgnore`。
- 复杂 XML 裸 SQL 自己写租户条件，不假设插件一定覆盖。
- 平台账号（`tenant_id` 为空）的可见范围必须在 SQL 里写清楚，不靠默认行为。
