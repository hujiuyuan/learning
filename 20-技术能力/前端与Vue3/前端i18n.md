# 前端i18n

技能点：[[Vue3]] · 方法：vue-i18n 接入（待建） · 通用技能：[[前端与Vue3]]

**什么时候会遇到**：同一套前端要给不同语言的客户用；或者客户只要求英文，但代码里中英混排。

## 判断顺序

1. **先问是不是真多语言**：要「运行时可切换」，还是只要界面统一英文。后者不需要 i18n 框架。
2. **分三层看**：UI 组件库自身文案、前端业务文案、后端返回的 message。三层可能各有语言来源。
3. **看后端是否已 i18n**：如果后端按 messageCode 翻译（见 [[Spring应用与接口契约]]），前端只负责固定文案。
4. **看覆盖范围**：只有登录页翻译不算支持多语言；要按页面统计 `$t` 覆盖率。
5. **最后决定接不接**：接就整页接，不接就不要在少数页面留半套。

## 手段（smart-web-omp 的现状）

- **创建实例**：`createI18n({ locale, fallbackLocale: 'zh-cn', globalInjection: true, messages })`（`smart-web-omp/src/locales/index.js:21-26`）。
- **语言包**：`zh-cn.js` 与 `en.js` 各 39 行，只有 `login`、`user` 两组（`src/locales/lang/zh-cn.js:1-39`、`en.js:1-39`）。
- **UI 库语言**：Element Plus 的 `el_zh_cn`/`el_en` 合进 messages（`src/locales/index.js:4-19`）。
- **持久化**：语言存 `APP_LANG`，启动时读取（`src/locales/index.js:22`），设置页写入（`src/layout/components/setting.vue:46`、`:73`）。
- **模板用法**：`$t('login.signIn')`（`src/views/login/components/passwordForm.vue:21`）。
- **表单校验**：rules 的 message 用 `this.$t(...)`（`passwordForm.vue:43-46`）。
- **切换入口**：设置页下拉 zh-cn/en（`src/layout/components/setting.vue:8-13`）。

## 反例 / 边界

- **只翻了模板页**：业务页 `car/`、`goods/` 下 0 处 `$t`，派送拼车、出货任务全是硬编码英文。
- **切换语言只改这几页**：登录页和个人设置会变，业务页不变。
- **smart-web-wms 完全没接**：`package.json` 无 `vue-i18n`，`src` 里 0 处 `$t`；Naive UI 的 locale 写死 `enUS`（`src/App.vue:4-5`）。
- **后端文案独立**：即使前端切了语言，后端 message 仍按请求语言返回，两边可能不一致。
- 没做过翻译平台、key 校验、复数/日期本地化。

## 现在的规矩

1. 要么整页接 `$t`，要么不接；不把半接的页面写成「支持多语言」。
2. 新增文案先加 key，再写组件；不直接在模板里写死。
3. UI 库 locale 与业务语言包分开维护。
4. 后端 message 与前端固定文案分开排查；不能假设切了前端语言后端也跟着变。
5. 没有 i18n 的项目不说「全栈 i18n」。
