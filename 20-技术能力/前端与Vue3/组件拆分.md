# 组件拆分

技能点：[[Vue3]] · 方法：三层拆分（待建） · 通用技能：[[前端与Vue3]]

**什么时候会遇到**：新加一个业务页；同一段查询区/表格/弹窗在第二个页面又出现；单文件涨到几千行，改一处要滚半天。

## 判断顺序

1. **先看是不是「同一个页面」**：同一套字段、同一套接口，只是模块码不同 → 做成参数化页面，不复制。
2. **再分三层**：布局（壳）、页面（业务编排）、通用组件（查询/表格/弹窗/上传）。
3. **出现第三次才抽象**：两处相似先忍着，第三处再抽通用组件。
4. **按变化频率分**：布局和通用组件变化慢，业务块变化快；变化快的留在页面里。
5. **最后看行数**：一个 `.vue` 超过约 1000 行，就先列拆分点，再决定动不动。

## 手段

- **布局层**：`layouts/full|normal|simple|empty` 四套壳（`smart-web-wms/src/layouts/`）；`App.vue` 按 `route.meta.layout` 异步加载并缓存（`src/App.vue:32-40`、`:87-91`）。
- **页面壳**：`CommonPage` 提供 header/action/footer 插槽（`src/components/common/CommonPage.vue:1-34`）；`AppPage` 提供整页滚动和返回顶部（`src/components/common/AppPage.vue:1-36`）。
- **查询区 + 表格容器**：`MeCrud` 只包查询区和插槽（`tableTop`、默认、`table`、`other`），对外发 `search`/`reset`（`src/components/me/crud/index.vue:1-87`、`:115-116`）。
- **弹窗**：`MeModal` 统一标题、footer、loading、拖拽（`src/components/me/modal/index.vue:1-70`）。
- **查询项**：`MeQueryItem` 负责单行样式和 vnode 渲染（`src/components/me/crud/QueryItem.vue:1-40`）。
- **上传**：`ImageCardUpload` 用 Naive UI 的 `custom-request` 接自己的分片逻辑（`src/components/common/ImageCardUpload.vue:1-60`）。
- **薄壳复用**：`packingList.vue` 只传 `module-code`，把 `wms.vue` 当模块页复用（`src/views/packing-list/packingList.vue:1-10`）。
- **页面组合**：`warehouse.vue:2266`、`shippingTask.vue:2187` 从 `@/components` 一次引入 `CommonPage/MeCrud/MeModal/MeQueryItem`。

## 反例 / 边界

- **壳拆了，业务没拆**：`shippingTask.vue` 6958 行、`warehouse.vue` 6239 行、`wms.vue` 4769 行；查询和弹窗是组件，表格列、弹窗内容、业务函数仍在一个文件里。
- **参数化页面不是组件**：`wms.vue` 靠 `moduleCode` prop 切模块（`src/views/wms/wms.vue:1606-1608`、`:1830`），改一个模块会影响所有模块。
- **MeCrud 不管表格和分页**：它只包查询区，表格、分页、勾选仍由页面自己写。
- **抽象过早**：只出现一次就抽通用组件，会让组件长满业务参数。
- 没做过独立业务组件库、monorepo 分包。
- omp 走另一条路：全局注册 `scTable/scDialog/scForm` 等一批组件（`smart-web-omp/src/scui.js:46-63`），没有按目录分层。

## 现在的规矩

1. 新页面先选壳：整页滚动用 `AppPage`，带标题/操作区用 `CommonPage`。
2. 查询区从 `MeCrud` 起手；表格和分页留在页面，除非第三次复用。
3. 通用组件只放 `src/components/common`，业务组件留在 `views/<模块>/`。
4. 单文件过千行就写拆分清单，不为拆而拆。
5. 复用页面用 prop 参数化，复制整页是最后手段。
