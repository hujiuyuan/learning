# muou 2026-11 落地记录

主项目页：[[muou]]。本页只记 2026-10-30 之后新落地或改口径的部分，逐条给代码、设计或提交证据；没有证据的不写。

## 1. 模块门控三条件同源

- **落地**：模块可用性收成 platform 一处判定：期次 → `enabled` → 档位序；`available` 由 `lockedReason == null` 派生，原因顺序固定 `phase_not_ready → module_disabled → plan_too_low`。套餐页 `API-12-039`、总会端导航 `API-12-083`、服务间 `API-12-062`、可用模块数 `API-12-054` 同口径；属会端 `API-12-003` 另判五门。
- **入口**：运营端维护页 + `module_gate.toggle_enabled` 审计；后台导航 `ModuleGateBox` 拦截页与菜单置灰；iam 权限树读 `API-12-062`。
- **证据**：`muou-server-platform` `aa1ebf9`、`a26bc7a`、`aad2c17`、`9733062`、`d08cc3b`；`muou-server-iam` `c844c003`；`muou-admin` `0aeba3df`；设计 `12-07-对外接口清单.md:1166`、`:1517-1524`、`:1703`；代码 `PlatModuleGateConstants.java:70-97`、`ModuleGateRow.java:18-36`、`ModuleGateBox.tsx:21-42`。
- **边界**：五门（`coop/配额/依赖`）未并入三条件；六档原因码里另外三档仍是保留位；没有真实套餐运营数据对账。

## 2. 敏感字段按权限单次揭示

- **落地**：详情只给掩码；明文走 `revealPii`：`pii_reveal` 能力与 `read` 分开，member 再叠 `member.pii.reveal`；事由必填，字段白名单 `idNo/phone/email`；一次访问一行 `sensitive_access_log`（含逐字段子表），解密与留痕同事务；响应返回 `expireSeconds=30` 与 `accessLogId`。
- **证据**：`muou-server-member` `7988ffcb`；`voidtech-server-archive` `c64618b`；设计 `17-03-03-档案台账与导出.md:352-386`、`17-02-表结构.md:358`、`:516-524`；代码 `PersonPiiService.java:25-35`、`PersonLedgerServiceImpl.java:282-380`、`RevealPiiResp.java:8-26`。

## 3. 人员更正驳回通知链

- **落地**：member 新增通知意图表 `member_person_correction_notice`（状态 `prepared/ready/retry/done/cancelled/failed`）与投递尝试子表；审核命令先落意图，再按意图发 outbox，并回源核对收件事实。终态 `done/cancelled/failed` 不可复活；发布只认「守卫实际移动了行」，受影响行数为 0 不发布。notify 侧持久受理并复用正式重试链；同码多模板按最早创建的一条确定性发送并告警。ops 登记 `member-person-correction-notice-retry` 补偿任务（每分钟）。
- **证据**：`muou-server-member` `b17958ab`、`e3bd204c`、`60406388`；`muou-server-notify` `4210c86`、`bec695f`；`muou-app-ops` `da35969`；迁移 `V202611042210__person_correction_notice_intent.sql`；代码 `PersonCorrectionNoticeService.java:70-110`、`PersonCorrectionNoticeStore.java:57-67`、`R__muou_jobs.sql`。
- **边界**：只覆盖人员更正驳回这一种通知；同码多模板是业务层保证唯一、库上没有约束；补偿任务是每分钟批量，时延未压测。

## 4. 审计的来源 IP 与系统收尾口径

- **落地**：客户端 IP 由网关从入站请求取一次（`getRemoteAddr()`），归一化为代理链首段、去掉 IPv6 方括号后写进上下文令牌；审计从 `MuouContext.clientIp()` 取值落 `ip` 列。请求事务内的系统收尾（材料准备租约到期）统一记 `operator_name=system`、`operator_id` 为空，不带触发方的 ip/trace；没有建行凭据时记告警、不写审计。
- **证据**：`muou-server-gateway` `8cbb637`；`muou-common` `100c215`；`voidtech-server-archive` `7e6343c`、`d6b43f5`；迁移 `V202611062200__archive_audit_log_operator_comment.sql:1-4`；代码 `ContextTokenIssuingFilter.java:547-559`、`AuditEnvelopeBuilder.java:36`、`:97-124`、`ArchiveAuditWriter.java`。
- **边界**：`operator_side` 仍只有 `admin/site/platform` 三档，没有 `system`；定时任务不写这张审计表，留痕走应用日志与调度中心；地址掩码只覆盖审计里的地址字段，其他明文面未推广。

## 5. Seata 事务日志 db 模式与测试 TC 隔离

- **落地**：TC 事务日志从 file 改为 PostgreSQL db 模式，本机与测试环境统一；`SEATA_STORE_MODE` 可临时退回 file。测试侧 `TestTcTarget` 启动前校验：host 必须是数字回环、端口必须显式、禁用原 TC / 运行 TC / 数据库端口（8091、18091、28091、5432、5434）；registry/config 必须 file，`grouplist` 只允许显式选定的单一测试 TC；不满足直接启动失败。
- **证据**：`muou-app-ops` `f0893dc`；`muou-common` `31de788`；`middleware/seata/resources/application.yml:57-76`、`middleware/seata/scripts/postgresql.sql`；`TestTcTarget.java:40-79`、`TestTcTargetSafetyTest.java`、`SeataTestDatabaseSafetyTest.java`。

## 7. 履历幂等键改按整份请求内容

- **落地**：档案履历写接口的幂等键从「`psn + catCode + date + title + correctionOf`」改为整份请求体字段按固定分隔拼接后取 SHA-256。同一天同一身份的两次不同动作（如两次会籍冻结原因不同）不再撞同一键；完全相同的请求重放仍命中同一行、返回原响应。旧五项键与带来源旧键保留只读兼容：请求体哈希相同才算重放。
- **证据**：`voidtech-server-archive` `a65a005`；设计 `17-02-表结构.md:516-524`；代码 `ArchiveIdempotency.java:25-33`、`:65-75`、`:99-118`；`ArchiveEventServiceImpl.java`；测试 `ArchiveEventServiceImplTest.java`。
- **边界**：只改了档案履历写口；其他写接口仍用各自的业务键；旧键的只读兼容没有做清理时限。
