这份记的是**我自己反复错的、和主动追问过的地方**。每条写清：错成什么样、正确理解是什么、现在过关没有。

## 一、反复错的

### 1. `np.zeros` 的形状要传一个元组（连猜三轮）

| 轮次 | 我写的 | 问题出在哪 |
| --- | --- | --- |
| 1 | `np.array(np.zeros[4], np.zeros[4], np.zeros[4])` | `np.zeros[4]` 把函数当下标用 —— **`[]` 是取值，`()` 才是调用** |
| 2 | `np.zeros(3, 4)` | 形状被拆成两个参数；第二个位置其实是 `dtype` |
| 3 | `np.array(np.zeros(3, 4))` | 外层再包一层没用 —— **错误在最内层就抛了** |
| 4 | `np.zeros((3, 4))` ✓ | 这是我示范之后写的 |

**正确理解**：形状本身**是一个元组**。双层括号不是新语法 —— 是「调用的括号」和「元组的括号」挨在一起：

```python
shape = (3, 4)        # 形状就是一个元组
a = np.zeros(shape)   # 调用 np.zeros，把整个元组传进去
# → np.zeros( (3, 4) )
#             ↑调用括号  ↑元组括号
```

写 `np.zeros(3, 4)` 时，第二个位置被当成 `dtype`，于是报 `TypeError: Cannot interpret '4' as a data type`。

**状态**：✓ 已过关（错题 m15，10-16 复习时用新题 `np.zeros(3, 4)` 复测一次答对，下次复习 10-22）

### 2. 「打印形状」写成了「打印数组」

题目要求 `print(b.shape)`，我写的是 `print(b)` —— 打出了数据，但没读出形状。而这一节的达标标准恰好是「会读出 shape」。

**正确理解**：`b` 是数组本身，`b.shape` 才是形状。两者打印出来完全不同：

```
print(b)        -> [ 0  1  2 ... 11]
print(b.shape)  -> (12,)
```

**状态**：✓ 已过关

### 3. 用了 Java 的两层下标 `c[1][2]`

我写了 `c[1][2]`，题目要的是 numpy 的 `c[1, 2]`。

**这个坑很阴**：取**单个元素**时两种写法结果一样（都是 `6`），所以察觉不到差别。差别只在**切片**时才暴露：

```python
c[0:2, 1]   # ✓ [1 5]  「前两行、第 1 列」
c[0:2][1]   # ✗ 这是「前两行里的第 2 行」，不是「取第 1 列」
```

**正确理解**：numpy 用**一对方括号 + 逗号分隔**；只有这种写法能跟切片混用。

**状态**：✓ 已过关

### 4. 形状写不出来 —— 不知道 `(2,)` 那个尾逗号

原话：「我不知道咋写明白么」「纯是你给的答案我本身还是看不懂」。

**正确理解**：形状是个**元组**，元组里**每个数字 = 那一个轴的长度**。

```
一维、长度 2   ->  (2,)
2 行 1 列      ->  (2, 1)
0 维（裸数字） ->  ()
```

一维那个逗号是 **Python 元组的语法**，不是 numpy 的：

```python
type((2,))   # tuple  ← 带逗号，这才是元组
type((2))    # int    ← 不带逗号，只是「2」加了层括号
```

**逗号才是元组的标志，括号只是分组** —— 证据：`t = 1, 2, 3` 没括号也是元组。

（我自己的总结，当时说对了，收进 [[numpy用法]] 第 3 节：**「形状纯表述几维 + 每个维度的元素个数，不表达元素内容」**）

**状态**：✓ 已过关

### 5. 把 `:2` 当成整数 `2`

把 `a[1:, :2]` 读成了「第二行的第三列」。

**正确理解 —— 判断口诀**：**只要这一格里出现了冒号 `:`，它就是切片，那一维就留着。**

| 写法 | 名字 | 意思 | 对那一维 |
| --- | --- | --- | --- |
| `2` | 整数 | 第 2 个 | **挤掉** |
| `:2` | 切片 | 从开头到下标 2 **之前**（＝第 0、1 个） | **留着** |
| `1:` | 切片 | 从下标 1 到**末尾** | **留着** |
| `:` | 切片 | 全部 | **留着** |

补完之后能自己推出新题：`a[0,:2]` → `(2,)`、`a[0,2:]` → `(1,)`。

**状态**：✓ 已过关

### 6. 「重排」这个词我不懂 —— 因为题目里用了没讲过的词

我在出题时凭空气引入了「重排」，教案和笔记里都没有。我的追问：「我没在你给我教案或笔记里看到重排这个字眼」。

**正确理解 —— 两把不同的尺子**：

| 尺子 | 测的是 |
| --- | --- |
| `np.shares_memory(a, b)` | 是不是**同一块内存**（视图 vs 副本） |
| 铺平回一维看顺序 | **读出来的顺序**有没有变 |

**「重排」= 数字在内存里的先后位置被真的搬动了**（如 `s.sort()`）。`a[::-1]` 是反例：它铺平回一维**复原不了**，但跟原数组**共享内存** —— 所以「铺平不能复原」推不出「重排」。

**状态**：✓ 已过关（这条主要怪我，已记进 [[numpy错误试探记录]]）

### 7. 把一维数组 `(5,)` 当成「竖着的一列」（第 5 节，错题 m17）

题目：`picks` 形状 `(4, 5)`，`fix` 形状 `(5,)`，问 `picks + fix` 能不能算。

我的答案：**不能算**，说「必须改成 `(5, 1)` 才能算」。

**实际情况正好相反**：

```
picks(4,5) + fix(5,)    -> ✓ 能算，结果 (4, 5)
picks(4,5) + (5,1)      -> ✗ ValueError: operands could not be broadcast
                            together with shapes (4,5) (5,1)
```

**根因**：我脑子里把 `(5,)` 想成了「竖着的一列」，所以觉得它对不上。实际上——

- **`(5,)` 是一维数组，它没有行、也没有列的概念。** shape 里只有 1 个数字 = 一维；有 2 个数字才是几行几列的表格。
- 从右往左对齐时，一维数组这**唯一的一位，对上的是最后一个维度（列方向）**，所以 `(5,)` 配得上 `(4,5)` 的 5 列。
- 写成 `(5, 1)` 反而变成**二维**了，它那个 5 对上了**行方向**，而 `picks` 只有 4 行 → 5≠4 → 报错。

| | `(5,)` | `(5,1)` |
| --- | --- | --- |
| 方括号层数 | 一层 `[1 2 3 4 5]` | 两层 `[[1],[2],[3],[4],[5]]` |
| 维度 | 1 维 | 2 维 |
| 取数 | `b[0]` | `b[0, 0]` |
| 跟 `(4,5)` 加 | ✓ 结果 `(4,5)` | ✗ 报错 |
| 相加时 | 复制成 4 行，**按列**配 | 想按行配，5 对 4，配不上 |

**状态**：✓ 已过关（10-20 复习：自己说出「`np.ones(4)` 可以理解为 `(1,4)`，第二维都是 4，所以能加」，方向完全正确；结果 `(6,4)`。补位的方向感建立起来了）

| 「`(5,)` 和 `(5,1)` 的区别是啥」 | 见上面第 7 条 |

| 「`np.array([[1],[1],[1],[1],[1]])` 这个结果是几维的」 | **二维**，形状 `(5, 1)`。两层方括号 = 二维；`np.array([1,1,1,1,1])` 才是一维 `(5,)` |

## 三、这批错误说明了什么（元规律）

**我踩的坑全部集中在「numpy 特有的表达方式」上**：形状怎么写、下标怎么念、参数怎么传。

第 5 节（axis / 广播 / `@`）又一次印证了同一条：

- **算得对不对，我基本没出过错**：`sum(axis=0)` 的结果 `[37 67 97 127]` 我自己算对了；补全题 `sales.sum(axis=0)` 一次填对，结果 `[200 200 260]` 的值和形状都推对了；矩阵乘法「结果第 3 行第 2 列 = A3·E1 + B3·E2 + C3·E3」也是一次推对。
- **错的全在「形状怎么念」上**：`(5,)` 当成一列（第 7 条）、结果形状误答成 `(3,3)`（`(5,3)@(3,2)` 实际是 `(5,2)`）、`(5,)` 的结果误答成 `(1,5)`。

所以：**要花力气练的是「写法和读法」，不是数学直觉。** 看代码、抄写法、把输出跟预期对一遍，比反复推原理更有效。

- **10-21**：广播两个方向都验过。`(5,4)+(5,1)` ✓、`(5,4)+np.ones(5)` ✗、`(6,4)+(4,)` ✓、`(6,4)+(4,1)` ✗、`(6,1)+(2,1)` ✗。
- **自己总结对的两条**（原话）：①「本质是能不能找到一个共同形状，让两边都复制得出来」；②「被拓展的那一维只能是 1」。这两句就是完整规则。
- **还剩一个坑**：「以为形状必须和原式相同」—— `(1,4)` 和 `(5,4)` 不一样也能加，因为 1 能复制成 5。所以「每门课一个数」写 `(4,)`（✓），写成 `(4,1)` 反而报错（行 5 vs 4）。
- **10-21 继续**：`y = X @ w + b` 整条流程走通——自己算出 `(4,1)`、4 个预测值 `[9 8 19 18]`，`err = [0,0,0,-2]`、`J = 0.5` 也算对了。

- **10-21 晚上**：梯度下降手推 + 跑通。1 特征、2 样本，`w` 从 3 出发，20 步到 `2.0032`，`J` 从 `1.25` → `0.0000`；自己看出「步子越来越小」是因为梯度越来越小。

- **他自己定的原则**：公式不背，记一句话版本「误差 × 特征，加起来平均」。
- **下次**：真实数据 + 多特征 + 带 `b` 的线性回归（正好用上 `@` 和广播），把前向 → 损失 → 训练连成一条。
