# 技能图谱草稿规范

## 输出位置

- 认证与授权：`_meta/drafts/认证与授权/`
- 数据访问与 ORM：`_meta/drafts/数据访问与ORM/`

只写这两个目录，不要改 `20-技术能力/`、`30-项目证据/`、`README.md`、`.obsidian/`。

## 通用要求

- 中文，短句，先结论；不写教科书。
- 每条「我做过」必须有 `路径:行号`；没有就降级为「设计/方案」或「学习中」。
- 计划文档标「设计/方案」，代码/测试标「实战」；不要把 plan 的复选框当成已完成。
- 双链只链本批页面或已存在页面；未建页面用纯文本 +「待建」，不要产生红链。
- frontmatter 不加 `通用技能:`、`状态:`、`业务模块:`。
- 每页尽量短；场景页 40–70 行，实践页 40–80 行，通用技能页 60–100 行。

## 页面模板

### 通用技能

```yaml
---
type: 通用技能
域: 后端
证据: 实战/设计
---
```

正文：

```markdown
# 名称

**一句话**：...

## 一、理论：...
## 二、实际使用：我在哪里用过
## 三、归纳：通用清单
## 四、回到理论
## 五、边界
```

```yaml
---

```

```yaml
---
```

```yaml
项目: [smart WMS]
```


> 「选型与取舍」不是可选项：至少写「当时的问题、候选方案（含不用它）、各方案代价、为什么选这个、什么条件下反悔」。只写做法不写理由的页面，按未完成处理。样板见 `20-技术能力/后端/数据访问与ORM/MyBatis-Plus/软删除.md`。
