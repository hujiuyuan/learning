# 技术能力拆分报告（讨论稿）

> 日期：2026-10-29
> 目的：比较三种技术能力粒度，选定后再建卡。
> 证据边界：实际用过 + 只读过都收；只读过的单独标「只读」，不写成「我解决过」。

---

## 0. 结论

推荐 **方案 B（能力点级，约 40 个节点）**。

理由：

1. 一个节点刚好能独立说清「这个技术怎么用 + 坑在哪」，查起来不粗不碎。
2. 方案 A 会把高价值细节埋进大卡，例如「Spring Security 的数据权限」「时区改造」只能当 Spring 卡里的一节。
3. 方案 C 会把同一个问题的知识拆散，例如时区改造会同时落到 Java 时间、Jackson、MySQL、前端日期四张卡，维护和跳转都变重。
4. B 是可扩展的：某个知识点以后长胖了（比如时区改造），再单独升成一张卡，不用一开始就拆到底。

---

## 1. 三种粒度对比

| | A 技术栈级 | B 能力点级 | C 知识点级 |
| --- | --- | --- | --- |
| 节点数 | 约 20 | 约 40 | 约 70 |
| 一个节点是什么 | 一个框架/库 | 一个能独立说清「怎么用 + 坑在哪」的技术点 | 一个具体机制 |
| 例子 | 「Spring」一张卡 | 「Spring Security」「Spring 事务」各一张 | 「认证过滤器链」「事务传播」各一张 |
| 适合查 | Spring 我大概会什么 | Spring Security 的数据权限怎么做 | 事务为什么失效 |
| 代价 | 细节埋在大卡里 | 平衡 | 碎片化、重复、维护重 |

## 4. 方案 C：知识点级（约 70 个）

| --- | --- | --- |

| Vue 3 | 响应式、组件通信、路由守卫、权限菜单 | 4 |
| Playwright | fixture/采集、trace、报告、重试与不稳定 | 4 |
| Claude Code | Skill、Agent、Plugin、Hook、MCP | 5 |
| numpy | shape、axis、广播、`@`、reshape/视图 | 5 |

## 5. 只读技术怎么处理

按你的要求，**读过但没上手的技术也收**，但卡的类型不同，不能写成「我解决过」。

### 只读候选

- `yudao-cloud`：Spring Cloud、MyBatis、多租户、代码生成器、Vben5 前端模板
- `yudao-ui-admin-vue3`：Vue 3 + Vben Admin
- `java-template-engine`：Java 模板引擎
- `ebo-admin-cn` / `ebo-web-nuxt`：如果只是看或少量改
- 其它只读过源码、没有实际排障记录的技术

### 只读卡模板

```markdown
# Spring Cloud（只读）

证据类型：只读

我读懂了什么：
- 服务拆分、网关、注册配置中心怎么配合
- 多租户/数据权限在框架里的落点

关键设计：
- ……

和我会的哪里不一样：
- 和我实际改过的 Spring Boot 单体项目相比，……

坑（来自源码/文档）：
- ……
```

**规则**：只读卡不写「症状 → 根因 → 我做的动作」，只写「我读懂了什么 / 关键设计 / 和我会的哪里不一样 / 文档里写的坑」。这样不会把读过的当成做过的。

## 6. 工程能力和技术能力怎么连

工程能力卡不重复技术细节，只列它依赖哪些技术卡。示例：

| --- | --- |

| 代码生成器与模板工程 | Velocity、PostgreSQL、Spring MVC/声明式 HTTP、Maven、数据建模 |
| 状态机与一致性 | Spring 事务与异常、SQL/索引/MySQL、Java 并发、WebSocket |
| E2E 报告体系 | Playwright、TypeScript、Vite/UI 组件库 |

| 教学型 Agent | Claude Code 扩展、Prompt/Agent 编排、numpy、导数与梯度下降、反向传播与字符 LM |

技术卡反向列 1–3 个「在哪些工程能力里用到」，项目页列全量。这样图有三条边：能力—技术、能力—项目、技术—项目。

## 7. 建议的建卡顺序

1. 先写 3 张样板：**Spring Security、PostgreSQL、Playwright**（后端 / 数据库 / 测试各一张），你确认格式。
2. 按栈批量：Java → Spring → 数据库 → 中间件 → 前端 → 桌面/AI → 测试 → AI 工具链 → 数学/LLM → 工具。
3. 技术卡稳定后，再写工程能力卡，引用技术卡。
4. 最后补项目证据页、业务索引、能力地图。
