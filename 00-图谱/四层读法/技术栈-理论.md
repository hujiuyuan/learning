# 技术栈（理论）

**定位**：这一层回答「应该会什么、为什么成立」，不回答「我在哪个项目做过」。基础能力页给自测题，技能点页的「方法总纲」「我会的部分」给机制和边界；做过的事在 [[中间件-实践运用]]。

## 怎么读

1. **先看基础页的「要能回答」**：能用自己的话讲清楚，才算过；讲不清的条目就是缺口。
2. **再看技能点页的「方法总纲」**：它把机制压成几条可执行的规则，比如 [[RocketMQ]] 的投递语义、[[Redis]] 的缓存降级。
3. **最后看「我会的部分」**：这里才是机制落到代码的细节；但仍然只回答「懂不懂」，不回答「做没做」。
4. **不要从「选型与取舍」开始**：没有理论和实践垫底，选型会读成产品对比；选型属于 [[项目方案]]。

## 边界

- 基础页不冒充实战：没有项目证据的条目只写「应该会什么」。
- 技能点页的「理论」只写到能解释项目里的做法，不抄教材；教材式展开留给基础页和外部资料。
- 同一技术在不同项目里的版本差异，以技能点页的版本说明为准（例如 [[Spring Boot]] 的 3.3.13 与 4.1.1 分开写）。
