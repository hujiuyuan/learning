# 四层读法

**一句话**：同一批技术页里本来就写着四层——理论回答「是什么/为什么」，实践回答「在哪用过/怎么接」，问题与原理回答「坏了怎么查/为什么坏」，项目方案回答「为什么这么选/怎么落地、代价是什么」。目录按能力归堆，这四层是读同一批页面的四个入口。

## 一张图

```
技术栈（理论）          中间件（实践运用）        问题与原理              项目方案
是什么、为什么     →    在哪用过、怎么接     →    坏了怎么查、为什么坏  →  为什么这么选、怎么落地
方法总纲/基础页         我用它干过什么/实践页      场景页/边界/失败模式      选型与取舍/项目证据
      ↑                                                                        │
      └──────────────────────── 反哺：方案改了，理论也要重写 ───────────────────┘
```

四层不是四个文件夹，而是四个问题。一个技术页通常同时带着四层：比如 [[RocketMQ]] 的「方法总纲」是理论，「我用它干过什么」和普通消息/Outbox 分工是实践，「重试/死信/堆积」和「边界」是问题与原理，「选型与取舍」和 [[muou]] 是项目方案。跨能力的通用机制另外抽到 `10-理论/`，避免每个中间件页各写一遍原理。

## 四层入口

| 层 | 回答的问题 | 主要页面 | 入口 |
| --- | --- | --- | --- |
| 技术栈（理论） | 这东西是什么、为什么成立、应该会什么 | `10-理论/` 的理论页、基础能力页、技能点页的「方法总纲」「我会的部分」 | [[技术栈-理论]] |
| 中间件（实践运用） | 在哪个项目用过、怎么接、失败怎么处理 | 通用技能页的「我用它干过什么」、实践页、中间件六件套 | [[中间件-实践运用]] |
| 问题与原理 | 出了什么故障、根因是什么、怎么验证、怎么修 | 场景页、方法页、各页「边界」「失败模式」 | [[问题与原理]] |
| 项目方案 | 为什么选它、代价是什么、怎么落地、什么条件反悔 | 技能点页的「选型与取舍」、项目证据页 | [[项目方案]] |

## 单页怎么读：以 RocketMQ 为例

1. **理论**：先看 [[中间件与异步任务基础]] 的 MQ 语义（投递/ack/重试/死信），再看 [[RocketMQ]] 的「方法总纲」。
2. **实践**：看 [[RocketMQ]] 的「我用它干过什么」：42 个监听器、`RocketMqTxMessageTransport` 同步发普通消息、Outbox 负责可靠投递。
3. **问题与原理**：看重试/死信测试和「边界」：为什么 Outbox 不把 RocketMQ 事务消息当主线、重复投递怎么消化。
4. **项目方案**：看「选型与取舍」：为什么 RabbitMQ 3.90 低于 RocketMQ 3.85、什么条件下反悔；再到 [[muou]] 看它在项目里的位置。

同一页里四层是连着的：理论解释实践为什么这么接，问题反过来暴露理论的边界，方案说明为什么接受这些边界。

## 目录地图

```
00-图谱/                     导航层
  四层读法/                  四个阅读入口（本页）
  技能地图.md                按能力组列全部技能
  技术栈索引.md              按技术列「有独立页/组内页/待建/未使用」
10-理论/                     跨能力机制层（理论页，不含产品操作）
  理论基础.md                理论索引 + 理论→中间件特性对照
  分布式系统理论.md / 消息系统理论.md / ...
20-技术能力/                 能力库（按域 → 组 → 技术归堆）
  <域>/<组>/
    <组>.md                  组页：理论 + 实践 + 边界，顶部有四层读法链接
    <组>基础.md              基础题索引（理论层）
    <技术>/<技术>.md         技能点页：方法总纲 + 实践 + 选型 + 边界
    <场景>.md / <实践>.md    问题与项目做法，跟最相关的技术放
30-项目证据/                 项目方案层：一个项目一页，按模块反查
```

能力库是「按东西归堆」，四层入口是「按问题指路」。同一页会出现在多个入口里，这是刻意设计，不是重复。

## 读法建议

- **新学一个技术**：理论 → 实践 → 问题。先知道它解决什么，再看项目怎么用，最后看它会怎么坏。
- **线上排障**：问题 → 理论 → 方案。先从现象和根因下手，再回头补原理，最后看是不是选型/方案的代价。
- **面试/复盘**：方案 → 问题 → 理论。先讲为什么选、代价是什么，再讲踩过的坑，最后补原理。
- **带人/写文档**：理论 → 方案 → 问题 → 实践。先给框架，再给决策，再给反例，最后给可抄的做法。

## 为什么目录不按四层物理切开

- **技能点页天然跨层**：[[RocketMQ]] 一页里同时有理论、实践、问题和选型；按四层切开会把同一页撕成四份，改一处要同步四处。
- **只把「跨能力机制」抽出去**：像共识、投递语义、B+ 树/LSM、Little 定律这种被多个产品页共用的原理，放在 `10-理论/`；某个产品的具体用法仍留在技术页。不是把所有「理论段落」都搬走。
- **能力组是检索单位**：排查「事务失效」时，人先想到的是「事务与状态一致性」这个能力组，不是「问题」这个类型。
- **四层是阅读路径，不是存储位置**：同一个页面在不同场景下会被从不同层进入；目录只负责归堆，入口负责指路。
