# 目录规则

## 顶层

| 目录 | 放什么 |
| --- | --- |
| `00-图谱/` | 入口页：技能地图、技术栈索引、目录规则 |
| `00-图谱/四层读法/` | 四层阅读入口：技术栈（理论）、中间件（实践运用）、问题与原理、项目方案 |
| `20-技术能力/` | 按能力组织的技术页 |
| `30-项目证据/` | 一个项目一页，做反查入口 |
| `_meta/` | 完成清单、路线图、对照表、报告；不参与图谱 |
| `01-Python基础/`、`03-numpy/`、`04-线性回归/`、`字典/` | 学习笔记，不强行并入技术能力 |

## 四层视图：读法，不是物理分层

同一批技术页里有四种读法，入口在 [[四层读法]]：

1. **技术栈（理论）**：基础能力页 + 技能点页的「方法总纲」「我会的部分」→ [[技术栈-理论]]
2. **中间件（实践运用）**：通用技能页的「我用它干过什么」+ 实践页 + 中间件六件套 → [[中间件-实践运用]]
3. **问题与原理**：场景页、方法页、各页的「边界」「失败模式」→ [[问题与原理]]
4. **项目方案**：技能点页的「选型与取舍」+ 项目证据页 → [[项目方案]]

不按四层物理切开，是因为一个技能点页天然跨四层（例如 [[RocketMQ]] 同时有理论、实践、重试/死信、选型），切开会把同一页撕成四份，改一处要同步四处。目录按能力归堆，四层按阅读目的指路；每个通用技能组页顶部都有一行「四层读法」链接，从组页可以直接跳到本组的理论、问题、方案。

## 20-技术能力：三层

```
20-技术能力/
  <域>/
    <通用技能组>/
      <通用技能组>.md          # 组索引（type: 通用技能）
      <通用技能组>基础.md      # 基础能力索引（type: 基础能力）
      <技术实例>/              # 技术页 + 场景/实践/方法
```

- **第一层是域**：`后端`、`数据库`、`前端`、`测试与质量`、`工程效率与AI`、`桌面与本地AI`。
- **第二层是通用技能组**：目录名必须和组页名一致。
- **组根放两张索引**：
  - `<组名>.md`：这个能力「是什么、我做过什么、边界」。
  - `<组名>基础.md`：基础题索引，只回答「应该会什么」。
  - 例外：跨技术组（如 `查询性能优化` 同时覆盖 MySQL/PostgreSQL）不强制组级基础页，基础页挂各技术实例。
- **技术实例放组内子目录**：目录名 = 技术名，里面至少有一张 `<技术>.md`；技术基础页叫 `<技术> 基础.md`。
- **场景/实践/方法**：跟哪个技术最相关就放那个技术目录；跨技术的放组根。
- **跨组技术实例**：放域级目录，例如 `数据库/PostgreSQL/`，由多个组链接过去，不复制多份。

## 类型与目录的关系

目录只负责「归堆」，页面角色看 frontmatter 的 `type`：

- `通用技能`：组索引，每个组一张。
- `基础能力`：组级或技术级基础索引。
- `技能点`：技术实例或方法总纲。
- `方法`、`场景`、`实践`：具体做法、问题、项目证据。
- `项目证据`：只放 `30-项目证据/`。

## 技术页的深度要求

页面不能只写「怎么做」。凡是出现「用 X」「统一用 X」「必须 X」的地方，都要能回答：

1. **当时要解决什么问题**：不用 X 会出什么故障、付什么成本。
2. **候选方案有哪些**：至少包括「维持现状/不用它」，以及同位置的替代方案。
3. **每个方案的代价**：失败模式、运维成本、迁移成本、对查询/契约/并发的影响。
4. **为什么选这个、什么条件下会反悔**：把决策条件和反悔条件写出来，而不是只写结论。

有项目证据的写 `路径:行号`；没有证据的推断标「推断」，不能包装成「当时想过」。样板见 `20-技术能力/后端/数据访问与ORM/MyBatis-Plus/软删除.md`：它对比了 `deleted_at` / `is_delete`、NULL / 固定值、原表软删 / 归档表，并写了唯一索引和索引选择性的代价。

## 命名

- 组页名 = 组目录名，例如 `认证与授权/认证与授权.md`。
- 技术页名 = 技术目录名，例如 `Spring Security/Spring Security.md`。
- 基础页统一后缀 `基础`：`认证与授权基础.md`、`MySQL 基础.md`、`Redis 基础.md`。
- 文件名不加序号；排序交给目录和链接。
- 全库不允许重名页面，避免 `[[双链]]` 指错。

## 例：查询性能优化

```
20-技术能力/数据库/查询性能优化/
  查询性能优化.md
  MySQL/
    MySQL.md
    MySQL 基础.md
    SQL 优化.md
    慢查询定位.md
    索引失效.md
    ...
```

PostgreSQL 同时服务查询、建模、多租户，所以放 `数据库/PostgreSQL/`，不塞进 `查询性能优化/`。

## 图谱颜色

`graph.json` 的 colorGroups 按页面 `type` 上色：

- 金色：`通用技能`
- 青绿：`基础能力`
- 蓝色：`技能点`
- 紫色：`方法`
- 橙色：`场景`
- 红色：`实践`
- 灰色：`项目证据`
- 深灰：`00-图谱` 入口页
- 绿色：Python / numpy / 线性回归学习笔记
